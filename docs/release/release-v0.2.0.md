- [x] Windows 兼容取词（2026-11-19）：**部分应用（自绘界面的编辑器、播放器等）根本不告诉
  系统「用户选中了什么」**，划词因此永远不出胶囊。划词页新增「有些应用读不到文字」卡片：
  用户把这类应用逐条加进名单后，在该应用里选中文字时，拾趣**代按一次复制键**把文字取出，
  取完立刻把剪贴板恢复成原来的内容。**默认名单为空 = 拾趣绝不代按任何键**，正常应用也不受影响
  （只有两条系统查询都读不到文本接口的应用才会走到这一步）。
  **利害关系（须在界面明示用户，不得含糊）**：按键是真实的，拾趣无法知道目标应用此刻
  显示的是编辑区还是终端——所以主键选 **Ctrl+Insert**（它在终端里不是中断信号，实测 Zed /
  终端 / Chrome / VS Code 都能取到词），只有该应用不认这根键时才改用 **Ctrl+C** 兜底；
  名单里加了带集成终端的编辑器、在终端区拖选且主键不认时，这次兜底的 Ctrl+C 会
  **中断正在运行的命令**（残余风险收窄为这一种叠加情形，未消除）；剪贴板里刚复制了文件或截图时拾趣直接放弃这次取词（还原不了非文本
  内容，宁可不出现也不替换用户刚复制的东西）。这是「按应用授权、默认关闭」而非全局常开的
  根本原因，与 macOS 常开兼容模式的差异、键序的实测依据均记录在 ADR-05（含翻案条件）。
  为免用户不知道这里有开关：同一个应用**第三次**读不到文字时提示一次去哪开启（只提示、
  不代替用户授权，利害关系仍须在设置页那段说明里读到），同一应用本程序期间不再重复提示。
  验收：未添加应用时行为与本功能上线前完全一致（零按键）；添加 Zed 后在其编辑区划词能出
  胶囊、取词后剪贴板内容回到划词前；先复制一个文件再划词 → 不出胶囊且文件的复制不受影响；
  移除名单条目即时生效（无需保存）；黑名单里的应用即使误加进名单也不代按键；提权应用仍读不到
  （按键被系统拦截，日志有记录，界面不报错）；未授权应用连续读不到第三次提示一次、第四次起
  不再提示，已在名单里的应用与黑名单里的应用都不提示，提示是纯文字、不带任何一键授权，
  4 秒自动消失且**点一下就收场**（不得出现挂住关不掉、又点不动的提示）。
  键序验收：名单里的应用划词命中时日志给出用的是哪根键；主键取到词的场合全程不出现
  Ctrl+C；主键不认的应用才见兜底记录（该场合胶囊最多多等约 0.6 秒）。

- [x] 选中内容是文件位置时打开该位置（2026-11-19）：划到**整段就是一个本机路径**的选区
  （如 `E:\Project\Magpie`、`C:\Program Files\...`，或地址栏里的 `file:///E:/`）时，
  「提取信息」里出现「打开位置」：目录**打开那个目录**，文件**在文件管理器里把它选中**——
  默认动作只是"带我去看它在哪"，不启动任何东西。只有文档与图片这类常见扩展名
  （txt / md / pdf / docx / png …）放行给系统默认应用直接打开；**可执行类
  （exe / bat / cmd / ps1 / msi / lnk …）一律只显示、绝不运行**——选区文本来自屏幕上
  任意内容，不能当成用户意图的凭证。
  WSL 发行版路径（`\\wsl.localhost\Ubuntu\home\me\Project`，旧别名 `\\wsl$\`
  同样收下）2026-11-19 点名要支持，本版收下：它写起来是 UNC，但这条命名空间由 Windows
  自己提供，资源管理器原生能进去，不开网络会话也不要凭据，和共享盘不是一回事。WSL 里的
  Linux 文件常常没有扩展名，正好落在"只选中、不启动"那一档。
  本版边界（刻意的）：显隐只看语法，**不去问文件系统「这个路径在不在」**——划词热路径上
  不该多出一次磁盘查询（网络盘与未启动的 WSL 发行版，第一次访问能卡十几秒）。代价是不存在
  的路径也会出现动作，点了给一行「找不到这个位置」而不是报错窗。句子中间夹着的路径不出动作
  （选区必须整段就是路径：路径里常见空格，纯语法判断不了路径到哪结束，猜错会把人带到
  隔壁目录）。共享文件夹（`\\server\share`）与 `/home/...` 这类 POSIX 写法留接口不做：
  前者判在不在要发起 SMB 会话且可能弹凭据窗，后者是 Linux 的路径，在原生 Linux 上做才对。
  验收：划 `E:\Project` →「提取信息」出现「打开位置」，点一下打开该目录；划 `.md` 文件路径
  → 用默认应用打开该文件；划 `.exe` 路径 → 只在文件管理器里选中它、不启动；划
  `\\wsl.localhost\<发行版>\...` → 资源管理器进到那个目录；划 `E:\不存在`
  → 一行提示；划「日志在 E:\logs\a.log 里」→ 不出动作；关掉「打开位置」开关后动作消失、
  其他动作不受影响；划 `D:\2026\1031\x.md` 这类含数字的路径时不再冒出「复制验证码」。

- [x] Anki 主动接入与牌组/类型自选（2026-11-20）：连上 AnkiConnect 后若还没设默认牌组，
  主动弹确认问是否让拾趣创建「拾趣::单词卡/内容卡」配套牌组与笔记类型（点「我自己选」
  则取消）；设置页新增「默认牌组」「笔记类型」两个下拉，从 Anki 实拉的牌组/类型列表里
  挑，选完即生效，胶囊的「Anki」动作随即出现。此前「测试连接」只拉列表、从不设牌组，
  导致显示「已连接」却划词没有 Anki 动作——本次把「联通」和「接入」接成一条路。
  关键交互决策：显式选了牌组就尊重它，不再按划词长短自动分流回拾趣子牌组（自动分流
  只在用一键配置的配套模式下生效）；配套牌组+类型已存在时一键配置幂等、不重复创建。
  本次会话问过一次即止，用户选了牌组或建了配套后永不再弹。
  验收：连上 Anki 但未配置时弹确认；点「创建配套牌组」后划词出 Anki 动作、卡片进拾趣
  子牌组；点「我自己选」后从下拉挑已有牌组（如自己的 AIctionary）划词建卡，卡片确实进
  该牌组而非拾趣；选了自定义牌组后不再弹确认；卡片样式/字段填充与改动前一致。

- [ ] 交接给别的 app 的动作，成功后胶囊自己收场（2026-11-19）：搜索、打开链接、写邮件、
  加入日历、打开地图、打开位置这一族动作把注意力交给了另一个应用，成功之后胶囊留在屏幕上
  只是盖住新窗口的残留浮层，现在**成功即收起**，那一行回执改走全局提示；**失败时胶囊留在
  原地**给行内提示，因为下一步就是重试或换个动作，胶囊正好是那块操作面板。
  关键交互决策：判据是「注意力有没有交给别的 app」，不是逐个动作打点。复制 / 复制验证码 /
  复制号码不交给任何应用，照旧留在原地给行内回执；AI、机翻、词典的结果落进结果窗，本来就收；
  结果窗与钉图内的同类操作一律不牵连（阅读现场和钉住语义不能被一次外部打开带走）；
  「提取信息」面板是批量清单，用户会连着点几条，因此不自动收起、只给全局提示。
  验收：划一个 URL 点「打开链接」→ 浏览器起来、胶囊消失、屏幕上有行「已打开」；点「复制」→
  胶囊留着并给行内回执；打开失败（路径不存在、无可用的搜索引擎）→ 胶囊留着说清原因；
  在「提取信息」面板连点两条「打开位置」→ 面板不消失、每次都有一行看得见的提示；
  结果窗里点「加入日历」→ 结果窗与钉图状态不变。

- [ ] macOS 远控/虚拟机场景划词误发按键（2026-11-19）：运行拾趣时在向日葵、
  微软远程桌面等远控客户端或 VMware 等虚拟机窗口里打开文件夹、点选录入框，
  对面机器会自动键入字符（两次操作出现 "cc"）。原因是兼容模式兜底在这类
  窗口里模拟 ⌘C，合成按键被转发到对面机器且修饰键在转发中丢失。已对输入
  转发客户端（远控：向日葵/ToDesk/TeamViewer/微软远程桌面/RustDesk/AnyDesk
  等；虚拟机：VMware/Parallels/VirtualBox/UTM 等）跳过 ⌘C 兜底。验收：
  远控/虚拟机会话内框选/双击不再向对面注入任何字符；本机其他应用的兼容
  模式取词不受影响。
