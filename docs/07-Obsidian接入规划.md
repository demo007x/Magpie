# 07 · Obsidian 接入规划

> v1.0 · 2026-09-25 · 状态：已立项（用户定为最高优先级），未开始实现。
> 依据：用户决策（战场认知纠正——划词在浏览器内天然可用，网页剪藏是能力面延伸）+ Obsidian 社区场景调研（主流组合 = Daily Notes + Calendar + Dataview + Tasks + QuickAdd）+ Obsidian Web Clipper 模板配置模型基准。
> 实现时照本文件执行；与本文件冲突的新想法先改本文件再动代码。

## 0. 共享基座（所有功能共用）

### 0.1 连接机制（三级，按依赖从轻到重）

| 级别 | 机制 | 依赖 | 用途 |
|---|---|---|---|
| **L1 文件直写（主路径）** | Obsidian 库 = 纯 markdown 文件目录，`std::fs` 直接写入 | 零（无插件/无网络/无密钥，离线可用）；仅需用户授权 vault 目录 | Obsidian 的文件监视器自动检测外部修改并刷新——写入即出现在打开的 Obsidian 中 |
| L2 官方 URI | `obsidian://new?…`（系统协议唤起 Obsidian） | 零插件；会切走焦点 | L1 失败时的兜底 / 快速新建独立笔记 |
| L3 Advanced URI 插件 | `obsidian://adv-uri?daily=true&mode=append&heading=…` | 用户安装社区插件 | 标题下追加等进阶能力（升级路径，见 0.3） |

### 0.2 Vault 与路径配置

- **Vault 目录**：设置页目录选择器选择一次（交互先例 = app_picker 的系统面板模式）；存入 settings。
- **路径解析**：所有目标文件 = vault 相对路径；写入 = `vault_path + 相对路径`。
- **与 Obsidian Daily Notes 核心插件的互认**：日记文件命名默认 `yyyy-MM-DD.md`——与 Obsidian Daily Notes/Periodic Notes 插件的默认约定一致，**我们追加的文件就是用户真实的日记**（关键互操作点）。

### 0.3 Advanced URI 探测（零 API 升级路径）

检查 `<vault>/.obsidian/plugins/obsidian-advanced-uri/` 目录是否存在 → 存在即标记"可用"，追加类动作自动升级能力（标题下追加等）。纯目录探测，无 API 调用。

### 0.4 模板变量系统（对标 OWC 的 {{title}}/{{date}} 变量模型）

| 变量 | 含义 | 来源 |
|---|---|---|
| `{text}` | 选中文本 / 识别文字 | 捕获链路 |
| `{content}` | AI 动作输出（解释/总结/翻译结果） | AI 链路 |
| `{source}` | 来源应用名 / 页面标题 | 窗口标题（零成本） |
| `{date}` / `{time}` | 当前日期 / 时间 | 系统时钟 |
| `{due}` | 解析出的截止日期 | NSDataDetector（仅任务场景） |

模板在设置页以文本框编辑，**所见即所发**（交互先例 = Prompt 设置页）。日期解析复用 entities.rs 的 NSDataDetector 链路（DateHit）。

### 0.5 送达原则（不变）

**无状态一次性送达**：逐条即写即完，不建收藏箱、不做同步队列、不落第二份状态。写入失败 → toast 错误 + 内容保留在剪贴板兜底。

### 0.6 设置契约

settings 新增 `obsidian` 配置块（settings.rs 与 types.ts **两处同步**，契约纪律）：

```ts
obsidian: {
  vaultPath: string;        // vault 根目录（空 = 未配置，相关动作不出现）
  dailyFolder: string;      // 日记子目录（默认 ""，即 vault 根）
  dailyFileName: string;    // 默认 "yyyy-MM-DD"
  taskFile: string;         // 任务目标文件（默认空 = 当日日记）
  cardFolder: string;       // 知识卡目录（默认 "Cards"）
  templates: { excerpt: string; task: string; card: string };  // 三套预设模板，变量见 0.4
}
```

设置页新增「Obsidian」卡：vault 目录选择 + 日记目录 + 三套模板编辑（所见即所发）。未配置 vault 时，「存入 Obsidian」类动作不出现（与未配 Key 时 AI 动作置灰同款交互）。

## 1. 每日笔记追加（默认场景，最高频）

### 场景依据

Daily Notes + Calendar 是 Obsidian 最主流的工作流（Calendar 曾是最流行插件；日记是用户的操作中心——想法/引用/待办/会议要点全往当天日记里写）。QuickAdd 的 capture 模式（热键 → 输入 → 自动归档到日记、不开笔记）验证了该场景的频率与价值。

### 触发

- 胶囊动作「存入 Obsidian」（配置 vault 后作为常驻动作出现，可开关/排序）；
- 结果窗 footer「存入 Obsidian」按钮（翻译/解释/总结/识图的结果均可送）；
- 识图结果同链路（截图文字直接落日记）。

### 行为规格

1. 用户划词/识图得到文字 → 胶囊出现「存入 Obsidian」；
2. 点击 → 按摘录块模板格式化 → **追加到当日日记文件末尾**（文件不存在则创建）；
3. Obsidian 监视器自动刷新 → 内容出现在用户的日记里；
4. 微确认：胶囊按钮文字短暂变为「已存入 ✓」（复用 flash 机制）。

追加块默认模板：

```markdown
- **{time}** · 来源：{source}
  > {text}
```

### 依赖与实现

- 纯 `std::fs` 追加写入（O_APPEND 语义，末尾追加）；UTF-8；无锁（追加冲突概率极低，可接受）；
- 新增 Rust 命令 `obsidian_append(path: String, content: String) -> bool`（路径越界校验：必须位于 vault 内，防路径逃逸）。

### 配置

vault 目录、日记子目录、摘录块模板（变量见 0.4）。

### 边界

- Obsidian 未运行 → 照常写入（文件变更，下次打开可见）✓ 离线可用；
- 追加位置 = 文件末尾——若日记有 frontmatter 也无碍（frontmatter 在头部）；
- 写入失败（目录不存在/权限）→ toast 错误，不静默。

## 2. 快速捕获（即划即存模式）

### 场景依据

连续阅读时逐条摘录（读书/文献/网文划线），**胶囊反复弹出会毁掉阅读体验**——这是连续收集的核心交互死结。QuickAdd capture 模式（热键 → 输入 → 自动归档、不开笔记）证明"无 UI 捕获"是该场景的正确形态。

### 交互设计（已与用户对齐的方向）

- **进入**：热键切换「即划即存：开」（设置页可改键位），一次性轻提示；
- **模式中**：每次划词**不弹胶囊** → 微反馈一闪（"已收集 ✓"，<1 秒）→ 立即追加进当日日记（时间戳+来源，逐条落盘）→ 用户继续阅读/划下一段；
- **退出**：再按热键（或 Esc）→ 恢复正常胶囊行为。

**设计要点**：逐条即存、无缓冲、无批量——每条划词立即单独落盘（时间戳天然按序），完全符合"无状态一次性送达"原则，**不触碰"不建收藏箱"边界**。

### 依赖与实现

- 模式状态：TS 侧（悬浮窗实例内）或 Rust 侧静态（跨窗口一致性权衡后定，倾向 Rust 静态）；
- 模式中划词的分流点：capture detect_loop 在发 `selection://captured` 前检查模式态 → 命中则直接走追加链路 + 微确认 toast（复用 toast 系统），**跳过胶囊**；
- 模式中的识图：同样直接追加（识别文字落日记）。

### 配置

模式热键（默认 ⌥⇒O，可改）；目标复用「每日笔记追加」配置。

### 边界

- 模式中 Esc 语义 = 退出模式（而非收起胶囊）；
- 模式中识图快捷键照常可用（识别文字同样直落日记）。

## 3. 任务写入

### 场景依据

Tasks 插件 + 日记待办是 Obsidian 第二大工作流（Tasks 是社区必装清单常客；Dataview 聚合日记待办是最常见配置）。

### 触发

划选含日期的待办文字（如"周五前把报告发我"）→ 胶囊/结果窗出现「加入任务」动作（与「加入日历」并列的出口动作——两者共享 NSDataDetector 日期解析）。

### 行为规格

1. NSDataDetector 解析出截止日期（DateHit，已有链路）；
2. 按任务模板追加：`- [ ] 周五前把报告发我 📅 2026-09-26`；
3. 目标文件默认当日日记（与场景 1 同文件，任务与摘录同页共存）。

### 依赖与实现

- 复用 detect_dates 的 NSDataDetector 链路（日期解析为确定性能力，零 AI）；
- 任务模板遵循 Tasks 插件的 emoji 约定（`📅 yyyy-MM-DD`），与社区生态互认；
- 目标文件可配置为独立任务清单（如 `Tasks.md`），追加到末尾。

### 配置

任务文件路径（默认空 = 当日日记）；任务模板（默认 `- [ ] {text} 📅 {due}`）。

### 边界

- 未解析出日期 → 退化为普通摘录块（不强行造日期）；
- Tasks 插件的完成态同步（勾选后回写拾趣）不做——单向送达，Obsidian 内自行管理。

## 4. AI 知识卡

### 场景依据

Zettelkasten 文献笔记（literature note：标题=概念、引用块=原文、正文=讲解）+ AI 总结的组合——**"AI 动作 × Obsidian 接入"的独有能力**：单靠 Obsidian 插件没有 AI，单靠 AI 工具没有 vault 落地。

### 触发

划选概念/段落 → 「解释」或「总结」→ 结果窗 footer 出现「存为知识卡」→ 一键新建笔记。

### 行为规格

新建笔记到卡片目录，结构：

```markdown
---
title: 费米估算
source: 预览
created: 2026-09-25
tags:
  - 知识卡
---

> 原文引用块（选中文本）

AI 解释/总结正文……
```

- 文件名：`{date} {标题}.md`（标题取选中文本首行截断）；冲突 → 追加 `-2` 序号；
- Obsidian 自动索引 → 双链 `[[]]` 可直接引用该卡。

### 依赖与实现

- `obsidian_write_note(dir: String, name: String, content: String) -> bool`（新建文件，冲突序号，路径越界校验）；
- frontmatter 由 Rust 拼装（模板固化在代码，v1 不开放自定义 frontmatter 模板）。

### 配置

卡片目录（默认 `Cards/`）；标签（默认 `知识卡`）。

### 边界

- 图片/表格不进入知识卡（v1 纯文本）；
- 需已配置模型服务（AI 动作前置条件，与现有 AI 动作一致）。

## 5. 网页剪藏（选区 / 识图 / AI 链）

### 场景依据

浏览器内划词天然可用（Safari=AX、Chrome=轻推）+ 识图兜底视觉内容 + AI 处理链——系统级剪藏，浏览器外同样可用（Web Clipper 只能活在浏览器里）。

### 触发与行为

- **选区剪藏**：浏览器内划选 → 「存入 Obsidian」→ 按摘录块模板落库，**{source} = 页面标题**（窗口标题白捡）；
- **识图剪藏**：截图/视觉内容 → 识别文字 → 同链路落库（覆盖 Web Clipper 做不到的视觉内容）；
- **AI 链**：解释/总结的结果连原文带来源入 vault（拾趣独有组合）。

### 与 Web Clipper 的边界（明确不做/降级）

- **整页存档 / Reader 副本**：⚠️ 降级路径备而未排——Safari 经 Apple Events 注入提取脚本（高保真）；Chrome 走 URL 抓取 + readability 解析（中保真，SPA/登录页失效）；AX 全文流兜底（低）。天花板 = 干净文字存档，非版式复刻。**待选区剪藏验证后再议**；
- **页面内连续高亮标注**：已并入「即划即存模式」（逐条即存无缓冲），独立标注层不做；
- **站点级模板规则（OWC Template triggers 的 URL 模式匹配）**：v2 再议，v1 全局模板一套。

### 对标 OWC 模板配置的采纳清单（用户截图基准）

| OWC 概念 | 拾趣对应 | 状态 |
|---|---|---|
| Template triggers（URL 模式） | 来源应用规则 | v2 再议 |
| Note name（{{title}} 变量） | 知识卡文件名模板 | ✅ 功能 4 |
| Note location / Vault | vault + 卡片目录 | ✅ 基座 0.2 |
| Properties（frontmatter 键值） | 知识卡 frontmatter（固化模板） | ✅ 功能 4 |
| Note content（模板正文） | 摘录块/任务/知识卡模板 | ✅ 0.4 |

## 7. 实施顺序

| 阶段 | 交付 |
|---|---|
| **Phase 1（MVP）** | 基座（vault 目录选择 + 文件直写命令 + 设置卡）+ 每日笔记追加（摘录块）+ 胶囊/结果窗动作接入 |
| **Phase 2** | 即划即存模式 + 任务写入 |
| **Phase 3** | AI 知识卡 + Advanced URI 探测升级 |

## 8. 不做清单

- 多 vault 支持（v1 单 vault）；
- 双向同步 / 收藏箱 / 待同步队列（原则，见 0.5）；
- Dataview / Bases 等库内能力的介入（Obsidian 自己的领域）；
- 整页版式复刻（保真天花板 = 干净文字存档）；
- 页面内连续高亮标注层（已并入即划即存）。
