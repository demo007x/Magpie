# 08 · Anki 接入规划

> v1.1 · 2026-11-15 立项（11-16 配置面收敛）· 状态：本期交付（划词/结果一键成卡全量：
> 默认牌组 + ⌄ 选牌组 + {url} 溯源 + 自定义标签 + 配套笔记类型单词卡/内容卡）。
> 依据：同类产品用户诉求（Pot #89「单词本收藏和历史记录」、沉浸式翻译 #1332「保存单词
> 升级为学习辅助」、沙拉查词生词本生态）+ Anki 生态工作流验证（Yomitan mining 范式、
> Anki 官方手册 tags-over-decks）。
> 实现时照本文件执行；与本文件冲突的新想法先改本文件再动代码。

## 0. 立项依据

- **需求密度**：AnkiWeb 插件市场里「词典生词本 → Anki」搬运工具密密麻麻（Dict2Anki 系、
  shanbay2anki、MojiToAnki、kind2anki、Pleco to Anki……），不少已 Broken 靠 fork 续命——
  「划词 → 生词 → Anki」这条链路用户需求真实且现有方案体验差（查词→收藏→导出→同步→
  制卡五步流）。
- **交互范式**：Yomitan 官方 Wiki 的 Anki 集成 = 设置页一次配置默认牌组/笔记类型，之后
  悬停生词一键建卡、无逐卡选牌组——「默认牌组 + 一键」是经过数百万用户验证的交互。
- **归属策略**：Anki 官方手册明确推荐 tags-over-decks（"use tags and/or fields to
  classify"），FSRS 在单一牌组上优化效果更好——卡片进同一收词牌组 + 标签归类是官方
  推荐路径，不是权宜之计。

## 1. 交互定稿

### 1.1 入口与出现闸

- 动作 id `anki`（注册表 kind: "local"，与 obsidian 同族常驻动作）。
- **出现闸 = `anki.deck` 非空**（连接测试成功并选定牌组才算接入）——胶囊、结果窗动作行、
  设置页三处口径一致。未连接不出现；已连接后 Anki 未运行动作仍出现，点击时 toast 报错。
- **主钮**：点「Anki」→ 建卡到默认牌组，无面板无弹窗。
- **⌄ 菜单**：仅当缓存牌组数 > 1 时出现（单牌组直达即可，无意义菜单是噪音）——项名 =
  连接测试时缓存的牌组列表（`anki.decks`），点哪建哪。胶囊 chev 菜单 / 结果窗 chips /
  结果窗溢出堆 pmenu / Windows 分离卡菜单四条渲染路径同数据同语义。

### 1.2 反馈（三态 toast，全局 toast 窗口）

| 结果 | 提示 |
|---|---|
| 成功 | 已加入 Anki：{deck} |
| 重复（allowDuplicate=false） | Anki 中已有相同卡片 |
| 连接失败 / Anki 未启动 | 无法连接 Anki：请确认 Anki 已启动并安装 AnkiConnect 插件 |

失败提示直接展示 Rust 侧本地化错误（err.ankiUnreachable / err.ankiDuplicate / 其他），
前端不做二次兜底改写——三态语义在 Rust 侧分类完成。

### 1.3 变量语义（{text} / {result} 拆分，2026-11-15 定稿；空值语义同日二修）

- **{text} = 选中文本原文**，永不变化——正面用它才可预期（旧版择优语义会让正面在
  结果窗语境变成动作输出，已拆分修正）。
- **{result} = 结果窗内容**——结果窗建卡时是当前动作的输出（翻译/解释/总结等，
  含机器翻译与自定义动作，不止 AI），胶囊直建为空（见 §6 空值决策）。配套类型的
  「背面」字段出厂映射即此变量。

## 2. 归属策略（回应「卡片离散/无归属」）

1. **卡片自带溯源**：背面模板默认 `{source} · {date}\n{url}`——每张卡记得来自哪个应用/
   页面；Anki 浏览器按 URL 筛选即可看到同一来源的所有词。
2. **日期标签聚簇**：标签默认 `magpie {date}`（支持 {date}/{source} 变量）——按天聚簇、
   回溯零成本；顺着 Anki 官方 tags-over-decks 路径，不制造大量小牌组。
3. **显式归属留给 ⌄**：多领域用户（语言/考试分牌）用 ⌄ 菜单在划词瞬间选牌组——轻交互
   内保留决策点。
4. **整理是 Anki 侧的事**：不做收藏箱、不做中间库（无状态一次性送达立场）；「收藏了但
   不复习」是用户与 Anki 之间的事，Magpie 只负责想收的瞬间零成本。

## 3. AnkiConnect 交互细节

- 协议：POST `{action, version: 6, params}`，响应信封 `{result, error}`。
- 用到的 action：`version`（连接测试）、`deckNames`（⌄ 菜单与下拉缓存）、`modelNames`
  （笔记类型下拉缓存）、`modelFieldNames`（建卡时组装字段 + 设置页高级映射区展示）、
  `addNote`（`options.allowDuplicate=false`）。
- 地址仅允许回环（127.x / localhost / ::1，Rust 侧校验）——AnkiConnect 是本地明文 HTTP，
  防配置误填把划词内容发往外部。
- 超时 2s：本地服务无响应即视为不可达，给用户「请启动 Anki」的明确提示。
- 错误分类在 Rust 侧：send/超时 → ankiUnreachable；error 含 "duplicate" → ankiDuplicate；
  其余 → ankiError（附原文）。
- 字段组装：**零配置是主路径，出厂映射与智能默认都在建卡时兜底**（2026-11-15 从
  「连接测试预填进配置」改为建卡时兜底——预填把默认值写死进配置文件，换笔记类型即坏）。
  配套笔记类型（单词卡/内容卡）建卡时叠加出厂映射（shared/anki.ts，不落盘）：
  背面 = {result}、来源/链接/日期三件套；其余类型按字段顺序智能默认：第 1 字段 =
  {text}（Anki 以首字段查重，须为唯一标识）、恰好两字段的类型第 2 字段 = {result}
  （仅结果窗建卡时是 AI 输出；胶囊直建留空——「先存卡、复习时再补释义」的挖卡习惯，
  避免正背同文）。建卡时 TS 先拉 modelFieldNames 定序，逐字段做变量替换；Rust 过滤
  陈旧字段名（不属于该笔记类型）与空模板后转发，防 addNote 报未知字段/空卡。

## 4. 设置契约（settings.rs ↔ types.ts 双份手工同步，camelCase + 容器级 default）

```ts
anki: {
  connectUrl: string;              // 默认 "http://127.0.0.1:8765"
  deck: string;                    // 默认牌组（空 = 未接入）
  decks: string[];                 // ⌄ 菜单牌组缓存（连接探测实拉）
  models: string[];                // 笔记类型缓存（连接探测实拉；配套类型存在性判定）
  modelName: string;               // 默认 "Basic"
  tags: string;                    // 默认 "magpie {date}"（无配置面，标签按天聚簇）
}
```

模板出厂默认值在 `src/main/pages/labels.ts` 与 settings.rs Default 双份维护（与 Obsidian
模板同纪律）；「恢复默认」= 写回出厂值。

## 5. 设置页（Anki 页，接入分组）

- AnkiConnect 地址 + **连接自动检测**：打开页面与地址变化（防抖）即探测，保留手动
  「重新检测」按钮；成功显示 Anki 版本，实拉牌组/类型列表缓存进设置（随保存落盘）并
  启用默认牌组下拉；自动检测失败只柔和提示（「未检测到 Anki——启动后本页会自动
  连接」），手动检测失败展示 Rust 本地化错误。
- **一键创建 Anki 集合（子牌组 + 两类型，用户触发）**：单枚按钮——`createDeck`
  × 2（**子牌组** `拾趣::单词卡` / `拾趣::内容卡`，父牌组「拾趣」随首个子牌组自动
  出现）+ `createModel` × 2（幂等缺失才建），就绪后按钮退位为状态行。字段同构
  （正面/背面/来源/链接/日期），只差排版：**单词卡**居中大字（查词场景）、**内容卡**
  左对齐换行（摘录场景，即原「拾趣划词卡」更名）。模板用 Anki 条件替换 `{{#字段}}`
  包裹溯源行，空字段整块省略不留孤儿括号；背面/来源/链接/日期的出厂映射**不落盘**
  （shared/anki.ts 常量，建卡时叠加）。历史自定义类型保留使用（尊重用户选择），
  显示一行提示（「只按通用规则自动填充」）。治「任意单词卡类型塞长文本」的大字号
  叠行与空字段残留括号（2026-11-15 实测 UVBasic-English）。
- **划词 ⌄ 菜单 = 子牌组（即卡型）选择**（取代原牌组菜单）：配套就绪时 ⌄ 展开两项
  （单词卡/内容卡），点哪建哪；主按钮按划词长短自动路由，**牌组跟随路由落对应
  子牌组**。牌组无配置面（下拉已删）：配置项只剩地址与一键创建。
- **无字段映射配置面**（2026-11-16 砍）：拾趣只有 6 种数据（{text}/{result}/
  {source}/{date}/{time}/{url}），逐字段下拉是「什么都能配」的虚假暗示——自定义
  笔记类型常有十几个字段（音标/词典星级等），九个无数据可填。两种配套类型已覆盖
  全部数据面；自定义类型走建卡智能默认（首字段 = 选中文本），不再提供映射 UI。
- **无标签配置面**（2026-11-16）：标签走出厂默认 `magpie {date}`（按天聚簇，建卡时
  展开 {date}/{source} 变量）——好默认 + 无人改的配置不配拥有一张卡。

## 6. 已定决策

- 2026-11-15：v1/v2 合并一次性交付（⌄ 选牌组/{url}/自定义标签/字段映射全量），理由——
  仅字段映射稍重，其余复用现成机制，分两期反增交接成本。
- 2026-11-15：Anki 未运行时动作不隐现（配置过即常驻、点击报错）——定时探测会造成动作
  闪变，且与 Obsidian「配置即出现」口径一致。
- 2026-11-15：⌄ 菜单仅多牌组时出现（2026-10-25「不标记默认项」决策的延伸：单牌组的
  ⌄ 是噪音）。
- 2026-11-15：失败 toast 直接展示 Rust 本地化错误，前端不统一改写（obsidian 是单一失败
  态才前端兜底；Anki 需要区分重复/不可达，分类在 Rust 完成）。
- 2026-11-15：**配置合一**——废弃「正面/背面模板」平行配置，字段映射为唯一配置面
  （用户实测反馈：两套配置管同一件事，看到的与生效的不一致；且多字段类型全靠映射，
  平行模板冗余）。
- 2026-11-15：**{text} / {result} 拆分**——{text} 永远是选中文本原文（正面可预期）；
  新增 {result} = 结果窗当前动作输出（翻译/解释/总结等，不止 AI；用户实测反馈后由
  「AI 释义」更名，避免以偏概全），映射选项「结果窗内容」即此变量。
- 2026-11-15：**零配置 + 建卡时智能默认**（同类产品实证后的翻案）——废弃「连接测试时
  预填进配置」：预填把默认值写死进配置文件，换笔记类型即坏、且映射跨类型串配置。
  改为 fieldMappings 按笔记类型隔离、只存显式覆盖项，未配置字段建卡时兜底（第 1 字段
  = {text}、两字段类型第 2 字段 = {result}）。依据：Anki 主流用户只用 Basic/填空等
  内置类型、从不碰字段映射（社区新手共识）；唯一需要映射的是挖卡型用户，其交互习惯
  由 Yomitan 训练（per-model 字段映射、一次配好长期不碰）；沙拉查词 AnkiConnect 方式
  更是零配置；Obsidian_to_Anki 的「映射不自动跟随笔记类型」是其最高频用户卡点。
- 2026-11-15：**胶囊直建时 {result} 为空**——不做静默回落原文（配置看到的「结果窗
  内容」与拿到的必须一致；正背同文的卡没有复习价值）。留空符合「先存卡、复习时再补
  释义」的挖卡习惯；要背面有内容就从结果窗建卡。
- 2026-11-15：**连接自动检测**——设置页打开与地址变化即探测（保留手动按钮）：零配置
  主路径下「连接测试」不应是用户必须发现并点击的动作；手动按钮保留给排查场景。
- 2026-11-15：**配套笔记类型一键创建**——「换通用类型如 Basic 即可」是把问题甩回用户
  （实测反馈：UVBasic-English 建卡正面大字号叠行 + 空音标残留括号）。样式归属笔记
  类型的边界不变，但拾趣提供为划词卡设计的出厂类型：createModel 幂等创建 + 自动
  选中（出厂映射建卡时叠加、不落盘），用户已有类型仍可选。同类先例：沙拉查词官方
  教程即引导建专用类型。
- 2026-11-16：**配套类型拆双（单词卡/内容卡）+ 砍字段映射配置面**——用户实测定案：
  拾趣的数据面只有 6 种变量，逐字段下拉是「什么都能配」的虚假暗示（自定义类型
  十几个字段九个无数据可填）；两种配套类型（单词卡居中大字查词、内容卡长文换行
  摘录）即全覆盖，fieldMappings 从契约中删除。自定义类型走建卡智能默认，样式诉求
  归 Anki 笔记类型自身（§7 边界）。
- 2026-11-16：**笔记类型下拉删除，配套按钮即选择器**——下拉列出 Anki 全部类型
  （问答/填空/图片遮挡/用户自制），但拾趣真正支持的就两种配套类型，其余选项是
  兑现不了的支持暗示（多字段类型只填得到正面）。无下拉即无「幻影显示」选择值
  校正问题，probe 不再静默改写 modelName；非配套类型保留一行状态提示。
- 2026-11-16：**标签配置面删除**——`magpie {date}` 默认按天聚簇已满足需求，改标签
  是极少数人的极少数场景，不值得一张卡的注意力税；字段保留在契约中（建卡时展开
  变量），仅移除 UI。
- 2026-11-16：**配套类型自动路由（用户定案）**——「记录到单词卡还是内容卡」是划词
  瞬间的决定，设置页二选一无法同时满足两种需求；改为两类型一起创建、建卡时按
  划词长短自动路由（短→单词卡、长→内容卡）。字段同构使判错代价仅为排版，启发式
  可放宽；自定义类型优先级高于路由（尊重既有选择）。
- 2026-11-16：**一键创建含牌组「拾趣」+ ⌄ 菜单改类型选择（用户定案）**——createDeck
  也是 API 能力，牌组一并免配置；⌄ 从牌组列表改为「单词卡/内容卡」手动指定
  （与自动路由互补：主钮自动、⌄ 明示）。
- 2026-11-16：**子牌组形态（用户定案）**——用户期望「拾趣牌组下两项：单词卡/内容卡」，
  落为 Anki 原生子牌组（`拾趣::单词卡`/`拾趣::内容卡`）：复习点父牌组两子牌组一起来，
  牌组选择即卡型选择（进哪个子牌组用哪种类型排版）。牌组下拉随之删除——有了自己的
  牌组，下拉（列的是用户的旧牌组）就没有存在意义；牌组完全由程序管理。创建动作
  必须由用户点击按钮触发，不做任何自动创建。

## 7. 边界与已知取舍

- **卡片样式归属 Anki 笔记类型**：拾趣只把模板渲染结果填进字段，字号/排版/模板里的
  固定符号全部由所选笔记类型的模板与 CSS 决定。拾趣自建类型不改用户已有类型；用户
  自选单词卡等专用类型时，模板为其内容形态设计（2026-11-15 实测：UVBasic-English
  塞长段落出现大字号叠行、空音标残留括号）——用配套类型（单词卡/内容卡）或通用类型。
- OCR/截图流无来源 pid：{source}/{url} 为空，模板相应内容省略。
- 模板不校验 HTML：Anki 字段支持 HTML，用户自定义内容原样送达（所见即所发）。
- AnkiConnect 需用户在 Anki 安装插件（代码 2055492159）：连接失败 toast 文案已含指引，
  docs/08 为安装指引的权威出处。
- 「收藏了但不复习」（collector's fallacy）不在产品职责内。
