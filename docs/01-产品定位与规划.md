# 01 · 产品定位与发展规划

> v2.0 · 2026-09-19 · 取代原 01-PRD-MVP（MVP 已交付并超出原范围，历史规格与任务分解见 [05-执行计划](./05-MVP执行计划.md) 与 git 历史）

## 1. 一句话定位

**拾趣 (Magpie)**：屏幕上任何文字，鼠标一指，AI 就地处理、就地落地。
**鼠标触发的第一文本源入口枢纽**——向上承接所有触发（划词 / 识图 / 快捷键 / 托盘），向下分发到 AI 与用户自选的专业应用。

与巨头划词工具的一句话对照：**豆包是 AI 的终点，Magpie 是文字的出口**——AI 结果流向用户自己的知识体系，而不是锁死在对话窗口里。

## 2. 差异化（为什么是拾趣）

- **vs 豆包 / 飞书划词**：它们只触达"可选中的文本"，且锁定自家生态与模型；拾趣是**划词 + 识图双管线**，覆盖"看得见的一切文字"（图片 / 视频 / 扫描件 / 客户端 UI），模型 BYOK 不锁定。
- **vs PopClip**：验证了"划词动作条"品类 15 年（¥90 买断 + Setapp，200+ 扩展），但无识图、AI 靠扩展拼装、对非标准应用兼容性差、中文场景没做透。拾趣的兼容模式（微信 / Office 兜底）、原生 AI 流式、中文实体识别正是它的短板清单。
- **vs ima 类知识库**：不要求用户"建知识体系"——接入用户**已有的**笔记应用，Magpie 只做通路。
- **胜负手：豆包是 AI 的终点，拾趣是文字的出口**。豆包 / 飞书划词的所有产出都终结在自家生态里——复制是唯一的出口，内容无法流向用户自己的知识体系。这不是功能缺口，而是**商业结构决定的禁手**：接入 Notion / Obsidian 意味着帮用户把价值送出自家生态，与巨头的产品逻辑直接冲突，它们大概率永远不会做。中立枢纽因此是结构性的、可长期持有的位置。
- **立场护城河**：中立枢纽——模型用户自选、数据本地优先、分发通向任意应用。巨头的商业结构决定了它们做不到这个立场；技术本身无护城河，立场 + 平台深水活 + 用户配置资产才是。

## 3. 用户分层

| 优先级 | 人群 | 核心场景 |
|---|---|---|
| P0 | **有知识管理习惯的文字工作者**（已用 Notion / Obsidian / flomo / 备忘录沉淀内容的作者 / 编辑 / 译者 / 研究者 / 学生） | 高频处理"别人生产的文字"：引用、查证、翻译、注释、收集——且收集要有归宿，不是读完了事 |
| P1 | 重度阅读者 | 读论文 / 扫描 PDF / 视频课程——痛点是"字看得见但选不中" |
| P2 | 泛用户 | 划词翻译 / 查词——获客入口，不是价值锚点 |

增长渠道随 P0 收窄而明确：少数派、Obsidian 中文社区、flomo 用户群——这些人群已经在为"文字流向哪里"付费或投入，天然理解 Magpie 的立场。

产品边界：**不做程序员向功能**（报错解释、代码解释等），避免与开发者工具赛道正面竞争。

## 4. 产品原则

1. **入口不改变目的地**：用户的沉淀归宿（笔记应用等）在装 Magpie 之前已选定，Magpie 只缩短到达路径，六步变一步。
2. **接入而非自建下游**：不自建笔记 / 知识库 / 单词本。接入动作**无状态、一次性送达**——不建收藏箱、不做待同步队列、不做中间库（否则与所有接入对象变成竞争关系）。
3. **零配置可用**：基础动作（复制 / 搜索 / 识图）不依赖 API key；AI 动作 BYOK 是升级路径而非门槛，不让新功能默认依赖"先申请 key"。
4. **通用规则而非枚举**：识别 / 提取一律用模式与结构规则，不用白名单枚举。
5. **热路径即时性**：划词 → 弹条 ≤ 300ms；AI 是可选增强层，不拖慢确定性动作。

## 5. 已实现能力快照（v0.1.5）

- **划词捕获**：拖选 / 双击触发，CGEventTap + AX 双线程，兼容模式兜底（微信 / Office），应用黑名单，防打扰三原则
- **动作注册表（9 个）**：翻译 / 解释 / 总结（AI 流式，BYOK）+ 复制 / 搜索 / 打开链接 / 写邮件 / 复制验证码 / 复制号码；上下文智能提取（URL / 邮箱 / 验证码 / 电话，单实体一键直达，多实体进「提取信息」面板）
- **识图**：快捷键 / 托盘框选 → Vision OCR（独立 helper 子进程）→ 一步式识图翻译 / 解释 / 总结；钉图（Snipaste 式，可循环回 OCR）
- **翻译三通道**：AI 翻译 / 百度翻译 / DeepL，单击直达默认 + 二级切换
- **搜索**：6 内置引擎 + 任意 `{q}` 自定义引擎
- **结果窗**：独立常驻、钉住、拖动、记忆尺寸与位置、底部动作条
- **入口**：托盘菜单、4 个全局快捷键（⌥S/⌥T/⌥E/⌥D）、划词、截图

## 6. 发展方向（2026-09-19 战略）

核心架构判断：**统一动作模型**——内置动作、自定义 AI 动作、接入动作、workflow 步骤是同一套注册表的不同类型（`src/shared/actions.ts` 已有雏形；设置页的搜索引擎 `{q}` 模板编辑是现成交互先例）。以下按序演进，每步独立交付价值：

1. **划词收藏接入（胜负手，第一优先）**：这是定位的第一个实物证明——"豆包是 AI 的终点，Magpie 是文字的出口"要靠它成立。
   接入的模型是**动词分类，不是应用枚举**。完整动作空间分三个家族，共用同一张注册表（统一动作模型）：

   | 动词家族 | 动词 | 载体 | 现状 |
   |---|---|---|---|
   | ① AI 处理 | 翻译 / 解释 / 总结 / 改写 / 续写 / 追问 | 任意模型（BYOK） | 内置 3 个，自定义动作待开放 |
   | ② 确定性处理 | 复制 / 搜索 / 打开链接 / 实体提取 | 本地规则 | 已内置 |
   | ③ 落地收纳 | 收藏 / 任务 / 日程 / 发送 / 学习 / 引文 / 表格 | 用户已装的应用 | 未做，本条主攻 |

   竞品只占据 ① 且把结果锁死在对话窗里（②③ 断路）；Magpie 的模型是三个家族任意动词可达且可串联（划词 → 解释 → 存入 Obsidian）。
   ③ 的载体是用户内容的**归宿**，豆包 / 飞书是内容的加工站——不把加工站当归宿，否则又是一条内容进豆包的路。

   第一批接入仍以「收藏」动词落地（Notion / Obsidian / flomo / Apple 备忘录，候选待定：语雀 / 飞书文档 / Bear / Craft），
   因为它是 P0 用户最高频的动词；任务（滴答清单 / Things / Todoist）、学习（Anki / 欧路生词本）、引文（Zotero）等动词随后复制同一接入范式。
   价值在**带上下文的结构化发送**（正文 + 来源应用 + URL + 时间 + markdown 模板，`{text} {source} {url} {date}` 变量），
   不是花哨的粘贴键；收藏动作按用户各自接入的应用动态出现，同一用户可接多个应用、多场景多归宿。用户已有 Notion / Obsidian 的 key 或本地库，直接接入即可。
2. **自定义 AI 动作 + 结果窗追问**：翻译 / 解释 / 总结的 prompt 模板开放给用户编辑（学生要语法 / 句式 / 例句，译者只要干净翻译）；结果窗底部追问框，带原文与上一轮结果多轮对话。
3. **自定义 workflow**：用户定义多步骤链，AI 步骤与确定性步骤混排——"永远不知道用户划词后想做什么"的正解。
4. **方案分享 / 导入**：动作方案一键导出导入，每一份分享都是一次分发（增长引擎）。
5. **提取信息回归**：URL / 邮箱 / 验证码 / 电话的结构化识别模式，作为 workflow 步骤扩展到更多实体（诗文名句 / 文献出处 / 表格）。

## 7. 商业化（2026-09-19 决策）

- **先做大用户量**，不考虑短期收入；**基础功能永久免费** + 模型 BYOK 用户自担。
- **付费切线未定**：不预建付费基础设施，待用户配置行为数据决定（候选：接入目标数 / 模板能力 / workflow 数量）。
- **反面清单**：不做广告、不倒流用户数据、不绑自家模型赚 token 差价——立场即护城河，商业化不能背叛它。
- 品类付费模式已被验证：买断（PopClip $17）、订阅（HapiGO ¥98/年）、Setapp 池、免费+Pro（Raycast）并行存在。
