# A. 划词捕获（capture）

> 全项目风险最高模块，macOS 优先；Windows 已交付（0.1.14，UIA + WH_MOUSE_LL，见 §A.7）

## A.1 职责与非职责

- **职责**：全局监听鼠标 → 判定"选词动作" → 经 AX 读取选中文本 → 过滤（黑名单/自身/重复）→ 发 `selection://captured` / `selection://dismiss` 事件
- **非职责**：窗口显示（窗口管理）、文本处理（TS 层）

## A.2 组件结构

```
src-tauri/src/capture/
├── mod.rs          # CaptureEvent 定义、平台分发、启动入口
├── macos.rs        # macOS：CGEventTap + AX 查询（MVP 实现）
└── windows.rs      # Windows：UIA + WH_MOUSE_LL（0.1.14 正式实现，见 §A.7）
```

平台通过 `#[cfg(target_os = ...)]` 分发，两个后端实现同一签名：

```rust
pub fn start(app: &AppHandle, tx: Sender<CaptureEvent>, debounce_ms: u64);   // 内部自建线程
```

## A.3 macOS 实现

### A.3.1 双线程模型

```
[CGEventTap 线程]  CGEventTapCreate(kCGHIDEventTap, listen-only, mask=MouseDown|Up|Dragged|KeyDown(Esc))
        │  回调仅做一件事：把 (事件类型, 坐标, 时间戳) 扔进 mpsc channel
        ▼
[Worker 线程]  状态机（判定）→ 自适应防抖（拖选 30ms / 双击 200ms）→ AX 查询 → 过滤 → app_handle.emit(...)
```

> listen-only tap 不消费/修改事件，对用户无感，被系统自动禁用的风险极低；回调内不做任何重活（AX 查询绝不放进回调）。
>
> **tap 层级实测（2026-09，macOS 26 Intel）**：`kCGSessionEventTap` 收不到拖选事件（仅偶发单击），`kCGHIDEventTap` 全部正常 → 默认采用 HID 级，`SHICI_TAP=session` 环境变量可切回对照。此偏差需在 Windows/新版 macOS 上复核。

### A.3.2 选词判定状态机

| 输入 | 规则 |
|---|---|
| LeftMouseDown | 记录 `down_pos / down_time` |
| LeftMouseDragged | 更新 `last_pos` |
| LeftMouseUp | `drag_dist = |up - down|`；`is_double_click = (本次up时间 - 上次up时间 < 400ms) 且位移 < 10px` |
| 判定为选词 | `drag_dist > 6px` **或** `is_double_click` → 进入防抖查询；否则视为普通点击 |

- 防抖（自适应）：判定为选词后 `sleep` 再查 AX（等待应用完成选区更新）——拖选的选区随拖动实时更新，30ms 吸收抖动即可；双击/三击的选区是松手后应用计算的，沿用 `debounce_ms=200`
- Finder 文件交互闸门（在防抖与一切 AX 查询之前）：聚焦应用是 Finder 且聚焦元素不是文本框（AXTextField/AXTextArea/AXTextView/AXComboBox）→ 本次拖选/双击实为文件拖动/双击打开，直接跳过取词链。不放行的后果：Finder 图标视图的文件项是 `AXGroup>AXImage`（文件名标签不是文本节点），AX 链路全部落空 → 兼容模式模拟 ⌘C → Finder 把**选中项文件名**作为纯文本写入剪贴板 → 文件名被误捕为划词，胶囊误弹且用户剪贴板被短暂改写
- 非文本表面闸门（原控件拖拽闸门的一般化）：拖拽**起点**命中元素（含 ≤3 层祖先）属于"文本选区不可能开始的表面"——交互控件与可选中元素的完整角色表（AXScrollBar/AXSlider/AXValueIndicator/AXSplitter + AXButton/AXRadioButton/AXCheckBox/AXPopUpButton 按钮族 + AXToolbar/AXTabGroup + AXImage/AXLink + AXRow/AXTreeItem/AXListItem/AXOutline/AXTable/AXList 行项族 + AXMenu 族 + AXProgressIndicator 等，29 个）→ 滚动/调参/拖放/换位手势，整链跳过。划界原则是"表面能否产生文本选区"而非逐个应用打点——拖动 VSCode 标签页误弹胶囊、拖工具栏/书签、拖文件树/消息列表行、Finder 图标拖动，都是"形状像拖选但起点是非文本表面"的同一本质。未知角色/泛容器（AXGroup/AXWindow/AXScrollArea）/定位失败放行：Electron 未建 AX 树时命中元素退化为泛容器，不能误杀真选词，此时由查询侧应答证据闸兜底
- 非文本表面闸门的差分例外（2026-10-21）：起点分类拦得住"拖行换位"，但也连坐了"网页表格内拖选/双击"——Chromium 把网页表格暴露为 AXTable→AXRow→AXCell，表格文字的拖选起点必然命中行项族。例外判据＝差分应答：复用按下时读好的选区基线（down_baseline），松手后复核一次——出现**按下时不存在的新选区**（应答 ≠ 基线且非空）⇒ 这是拉出了真选区的文本手势，放行进正常查询链路（AX 应答证据闸再复核）；基线缺失（静音期/查询失败/聚焦在自身）/复核失败/应答与基线相同（遗留选区背书）⇒ 维持拦截。拖行换位类手势不会产生新选区，不回归；证据不足永远倾向拦截（误报代价大于漏报）
- Electron 编辑器家族兼容模式禁用：VSCode/Insiders/VSCodium/Cursor/Windsurf（`bid_in_editor_family`）跳过 ⌘C 兜底——该家族空选区 ⌘C 的行为是**复制光标所在行**，任何 AX 落空的拖拽（滚动条/文件树/标签页）都会把当前行误捕成划词；真选区经 Chromium 轻推后 AX 链路稳定可取。代价：用户手动关闭编辑器辅助功能支持（`accessibilitySupport: "off"`）时取词失效
- 普通单击：若浮动条当前可见 → 发 `selection://dismiss`（点击空白隐藏浮动条）

### A.3.3 文本查询链（AX 优先）

```
AXUIElementCreateSystemWide()
 → CopyAttributeValue(kAXFocusedApplicationAttribute) → 聚焦应用 app
    ├─ AXUIElementGetPid(app) → pid ①自身过滤 ②proc_pidpath 取应用路径→黑名单匹配
    └─ 文本查询链（按实现顺序，任一成功即返回；①②④⑤⑦ 的应答受证据闸约束，
        见下方「应答证据闸」）：
        ① 聚焦元素 AXSelectedText（主路径）
        ② 聚焦元素 AXSelectedTextRange → AXStringForRange（参数化范围回退，
          覆盖部分 Qt 自绘文本视图——不暴露 SelectedText 但支持范围取值）
        ③ 应用级 AXSelectedText（部分应用只在此暴露；无元素可锚定，不受证据闸约束）
        ④ Chromium/Electron 系轻推（AXEnhancedUserInterface / AXManualAccessibility
          置 true 后**有界轮询**①：每 100ms 探一次、上限 500ms、命中即提前续链——
          webview 类内容（markdown 预览、AI 侧栏）建树可达数百毫秒且树会被惰性
          收摊，固定短等待表现为「有时取到有时取不到」；VSCode 家族兼容模式被禁，
          此路径是其主通道）
        ⑤ 坐标定位：AXUIElementCopyElementAtPosition（top-left 原点，与 CGEvent 同系）
          取鼠标处元素 → 沿 AXParent 上溯（≤5 层）尝试①②，绕开聚焦链路
        ⑥ 兼容模式（常开兜底）：快照剪贴板 → CGEventPost 模拟 ⌘C →
          轮询剪贴板变化（10ms × 60，上限 600ms）→ 取词 → 还原快照
        ⑦ 有界子树扫描：聚焦元素子树 → 聚焦窗口子树（各 64 节点 / 深度 6，DFS 尝试①②）。
          覆盖聚焦元素停留在输入框、真实选区在兄弟/子孙节点的场景；
          仅 ⑥ 未命中时触发，可能超出 A.5 的 30ms 查询预算（失败兜底，可接受）

应答证据闸（AXSelectedText 是**状态查询**而非**手势结果查询**——编辑器里的遗留
选区（双击选词后长期残留）会让任何应答者背书一次从未发生的选区，拖动标签页
即以此误弹胶囊）：

- 角色白名单：应答元素必须是文本承载节点（AXTextArea/AXTextField/AXTextView/
  AXComboBox/AXStaticText）。真选区由文本叶节点应答（Chromium 给选区命中的
  static text 逐节点下发偏移）；文本叶节点独占应答失效的应用下沉到 ⑥ 兜底，
  捕获能力不受损
- 手势锚定：应答元素框架（AXPosition/AXSize，外扩 8px）须含对应手势点——
  ①②④ 锚定**按下点**（真拖选必然从选中文本内部开始），⑦ 锚定**松手点**
  （微信 Qt 桥的兄弟节点选区在拖放位置），⑤ 的起点本身即松手点、由角色闸
  把关。框架读取失败放行（不因辅助信息缺失拒绝主路径）
- 容器差分（聚焦元素路径的容器分支）：VSCode AI 侧栏等 webview 的选区主要在
  AXGroup/AXWebArea 级聚合暴露，一刀切除名会让这类划词时有时无，放行又让遗留
  选区复活（容器框架包含一切手势点，几何锚定失效）——改用差分证据：按下时读
  选区基线（focused pid + SelectedText），容器应答 ≠ 基线 ⇒ 选区在本次手势期间
  发生过变化 ⇒ 采信；相同 ⇒ 遗留选区原样背书 ⇒ 拒绝。基线缺失（按下时读失败/
  聚焦在自身/静音期）= 拒绝
- 树重建重试与轮询：Chromium 轻推/收摊的过渡态会让查询报 CannotComplete
  （-25212，聚焦应用/聚焦元素/坐标定位三处短等 100ms 单次重试）；webview 类
  内容建树耗时不定且树会被惰性收摊——轻推后的固定短等待是「有时取到有时取
  不到」的主要间歇源，改为有界轮询（见路径④）。实测还存在更深的过渡态：
  应用级读写全线 IllegalArgument（-25205）、**轻推写入本身也被拒**，稍后自愈、
  重写轻推即恢复——故轮询每轮重写一次 AXManualAccessibility。
  兼容模式跳过闸（编辑器家族）的聚焦判据在 AX 半死时会间歇失效，退回
  NSWorkspace frontmostApplication（不依赖 AX）兜底

    └─ Safari 专属分支（AX 链路失败且聚焦应用为 Safari 时，先于 ⑥ 执行）：
        osascript `do JavaScript "window.getSelection().toString()"` 读取选区
        （需 Safari 开发菜单开启「允许来自 Apple 事件的 JavaScript」；未开启/超时 → 落到 ⑥）
```

### A.3.3.1 兼容模式（模拟 ⌘C，常开兜底）

AX 链路全部失败时触发（行业通行解，参考 Easydict GUIDE / issue #84）：

```
快照剪贴板文本 → CGEventPost 模拟 ⌘C → 轮询剪贴板变化（10ms × 60，上限 600ms）
→ 取词 → 还原快照（原无文本则清空）→ 走正常 Selection 链路（黑名单/去重仍生效）
```

取词失败仍静默；剪贴板为非文本内容时无法还原（已知限制）。

- CF 内存管理：`Copy*` 返回 +1 引用，用 `CFString::wrap_under_create_rule` 接管，drop 自动 `CFRelease`
- **查询失败的语义 = 静默失败**：不发事件、不提示
- **定位（2026-09-22 定稿）**：所有取词路径统一「跟随鼠标上方」——胶囊水平中心对光标、卡片底边距光标 16px，屏顶放不下落到光标下方（豆包同款；业界弹出层间距惯例 12–16px，实测 12px 易误触取上限，见 ADR-06）。不做 AX `BoundsForRange` 选区锚定（Chromium/Electron 系不暴露选区几何，双轨定位体验分裂，实测后翻案）

### A.3.4 过滤规则（顺序即优先级）

1. `pid == 自身` → 跳过（主窗口/浮动条内选词不触发）
2. 应用 bundle 路径命中 `app_blacklist` → 跳过
3. 文本为空 / 与上次已捕获文本相同且坐标相近（< 4px）→ 跳过（重复触发抑制）

### A.3.5 权限

- 启动时 `AXIsProcessTrustedWithOptions(prompt=false)` → 发 `capture://permission`
- 自检页按钮：`AXIsProcessTrustedWithOptions(prompt=true)` + 打开 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`
- **输入监控（Input Monitoring）**：缺失时 listen-only tap 收不到其他应用的事件（浮动条不弹）；自检页经 `capture_status.listenEventAccess` 展示，`request_listen_access` 以 `CGRequestListenEventAccess` 发起授权，未通过时代开 `Privacy_ListenEvent` 面板
- **AX 服务实测**：`capture_status.axServiceOk` 以 system-wide 聚焦应用查询区分「TCC 信任」与「AX 服务实际放行」（缓存异常/代持授权时割裂）
- tap 创建失败（未授权时 CGEventTapCreate 返回 NULL）→ 重试定时器（每 3s），授权后自愈
- **开发模式授权**：`tauri dev` 的裸二进制不会出现在辅助功能列表，需给终端 App 授权或手动添加二进制——指引放 README（步骤①），不进产品 UI
- **打包版授权注意**：ad-hoc 签名下 TCC 以 CDHash 记录授权，**每次重新构建均需在「辅助功能 / 输入监控」中删除并重新添加**，否则列表看似已勾选、实际指纹失效

## A.4 事件载荷

```rust
pub struct CaptureEvent {
    pub text: String,     // 选中文本（原始，未 trim）
    pub x: f64,           // 鼠标全局坐标（macOS = logical point，与 Tauri LogicalPosition 同系）
    pub y: f64,
    pub app: String,      // 进程路径（黑名单/展示用）
    pub bid: String,      // bundle identifier（黑名单精确匹配，如 com.apple.Safari）
    pub pid: i32,         // 来源进程（自身过滤）
}
```

## A.5 性能预算（设计约束）

- 回调入队 < 10μs：回调只做入队，绝不查询 AX
- 防抖：自适应档位（拖选 30ms / 双击 200ms，见 A.3.2）
- AX 主路径查询 < 30ms（实测通常 < 5ms；兜底路径失败静默，不计入预算）
- 常驻开销：tap 线程阻塞在 RunLoop（0% CPU）；Worker 线程阻塞在 recv（0% CPU）

> 不写"松手→弹条"的端到端总量数字：它由防抖档位与前端渲染共同决定，代码与计时日志（⏱ 划词链路）是唯一真相。

## A.6 已知覆盖缺口（预期管理）

| 场景 | AX 可用性 | MVP 行为 |
|---|---|---|
| Safari | ⚠️ 不暴露 AX SelectedText | AppleScript 取词（需 开发菜单 → 允许来自 Apple 事件的 JavaScript）；未开启自动走 ⌘C 兜底 |
| Chrome / 备忘录 / VS Code | ✅ / ⚠️ 需轻推 | 正常 |
| Pages / Keynote / Word（自绘文本） | ❌ | 兼容模式（⌘C）取词 |
| 微信 4.x（Qt 自绘主界面） | ❌ 不暴露 SelectedText | 自动走兼容模式兜底（模拟 ⌘C），正常弹出 |
| 微信 3.x / QQ NT（Electron） | ✅ / ⚠️ 需轻推 | 正常 / 轻推后正常 |
| 部分 Electron 旧应用 | ⚠️ 取决于版本 | 兼容模式（⌘C）取词 |
| 自绘 UI 应用（部分 PDF 阅读器） | ❌ | 兼容模式（⌘C）取词 |
| 远程桌面 / 虚拟机内部 | ❌ | 兼容模式（⌘C）取词 |
| DRM 内容（如部分视频字幕） | ❌ | ⌘C 亦不可复制，静默失败 |

## A.7 Windows 预设计（M2）

- 监听：`SetWindowsHookEx(WH_MOUSE_LL)` 低级钩子（与 CGEventTap 对位）
- 查询：UI Automation —— mouseup 后 `ElementFromPoint` → **有界父链（≤8 层）找 `TextPattern::GetSelection` 非空选区** → `DocumentRange.GetText`。走父链是实证修正：聊天消息/网页正文的选区在 UIA 树里常挂在起点上层的文档节点（Chromium 系尤其如此），起点本身往往是 ListItem/Group 叶子，只查起点会概率性漏捕
- 闸门（A.3.3 的 Windows 对位）：**自身闸门** = pid 命中本进程，或点位根 HWND 属本进程——WebView2 内容的 UIA 元素报运行时进程（msedgewebview2.exe）的 pid，只查 pid 会漏掉自家面板文字的自捕获；**起点分类** = 手势同形控制表面（滚动条/按钮/标签页/文件树行 TreeItem/菜单等）在**按下点**命中即拒绝——按下的位置才是手势真正的开始，抬起点链上的容器（如网页外壳 Tab）不连坐，否则正常划选被误拒；**应答证据** = 「非空 TextPattern 选区」是唯一放行条件，沿抬起点父链（≤24 层）查找，父链无证据时以**焦点元素父链**兜底（仅当焦点与终点同进程，不做跨进程陈旧背书）
- 坐标：物理像素，需按 `DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2` 换算（与 macOS 不同系，窗口管理层统一封装）
- 已知坑：Chromium 系应用需激活 UIA 支持；提权应用（任务管理器）不可读；锚定/差分证据为 v2（应对 web 内容里「遗留选区 + 拖其他列表行」的残余误报面）

# B. 窗口与交互（UI）

> 覆盖浮动条窗口、主窗口、交互规格与视觉基调

## B.1 窗口规格

| 属性 | 浮动条 `floating` | 结果窗 `ocr` | 主窗口 `main` |
|---|---|---|---|
| 初始尺寸 | 336×54（胶囊） | 420×340 | 880×620 |
| 尺寸模型 | 宽度随内容自适应（`resize_floating`，现服务胶囊自身二级浮层；TS 未传宽度时 Rust 兜底 DEFAULT_W=328） | 用户拖拽缩放，钳制 320–560 × 200–800；尺寸只由拖动 / 外观预设改变且跨会话记忆（`floating.rs::apply_result_window_size`） | 可缩放（min 780×520） |
| 装饰 | 无边框、透明 | 无边框、透明 | 系统标准 |
| 层级 | 置顶 + 不进任务栏 | 置顶 + 不进任务栏 | 常规 |
| 焦点 | **不抢焦点**（不 show/focus，纯鼠标交互） | 默认不抢焦点，用户点击面板后才聚焦（使 Esc/⌘P/⌘W 键盘闭环） | 正常 |
| 定位 | `show_floating_bar(x,y)`：胶囊居中对齐光标、卡片底边距光标 16px，屏顶放不下翻到下方，防出屏钳制 | 三级优先：记忆位置 > 划词导流贴胶囊下方（8pt）> 首次识图主屏居中偏上；防出屏钳制 | 记忆位置 |
| 生命周期 | 常驻隐藏，show/hide | 常驻隐藏，show/hide | 常驻 |

### 防出屏钳制（设计意图）

窗口逻辑尺寸随内容测量（TS 渲染后上报），位置统一为逻辑坐标；钳制规则：水平居中对齐光标后钳制在显示器内，垂直默认贴光标上方、屏顶放不下翻到光标下方（见 A.3.3.1 定位说明与 ADR-06）。实现唯一真相在 `floating.rs::place()`，本文不复制参数——历史教训：镜像参数与代码漂移后比没有文档更毒。

### B.1.1 Windows 分离卡拓扑（方案甲「一卡一窗」）

macOS 的分离卡（胶囊 + 二级浮层同窗、卡间缝 + 出血由 NSWindow 按 alpha 轮廓画影）依赖的窗口能力 Windows 没有：DWM 阴影跟窗口矩形走，任何出血/缝隙都会原样透出桌面（「透明圈」反复出现的根因，多轮缓解均告失败）。Windows 对等结构改为**每张卡一扇零出血窗口**：

- `floating` = 胶囊卡；`floating-panel` = 收纳面板卡；`floating-menu` = 窄单列菜单卡（两者预建常驻隐藏，`floating.rs::init_pop_windows` 创建，仅 Windows 存在；macOS 零开销）。
- 窗口矩形 = 卡片矩形 → DWM 矩形阴影恰好就是卡片阴影；卡间缝是真实桌面，点击穿透到下层应用，钩子按缝外点击正常 dismiss（`rect_contains` 含全部可见卡，缝内不误关）。
- 圆角双轨：webview 底色常驻透明，CSS 8px 圆角是所有机器的兜底；DWM 窗口圆角（`DWMWA_WINDOW_CORNER_PREFERENCE = ROUND`）在肯裁的机器上顺带消掉 CSS 圆角压窗口边界的毛刺。注意 DWM 对无边框窗口**是否真的裁切因机器而异**（属性调用恒返回成功，部分机器如 Win11 ARM64 视觉不裁，与 THICKFRAME/CAPTION/透明与否均无关）——不得据此探测，也不得押注常驻不透明底色（曾致直角回归，0.1.15 教训）。`DWMWA_BORDER_COLOR = NONE` 去掉 1px 系统强调色边框（阴影保留）。结果窗拖拽缩放期间经 `set_result_window_opaque` 临时切不透明底色防「透明白闪」，松手恢复透明。
- 数据流：胶囊窗口是唯一业务端（选区上下文/动作执行/服务选择），弹层是哑渲染端。`set_floating_pops`（payload + 锚点，target = panel / menu / close-panel / close-menu / none）→ 弹层渲染量尺寸 → `pop_ready` → Rust 锚定翻转钳制定位显示（胶囊像素不动）。弹层点击经 `floating://pick` 回传胶囊执行（§3.2 契约表）。
- 事件投递的坑：Tauri v2 的全局 `listen()` 注册在 `EventTarget::Any` 上，`emit_to` 发给别的窗口的定向事件它也收得到——定向事件（`floating://pop` / `floating://pick`）必须用窗口作用域监听（`getCurrentWebviewWindow().listen`），否则两个弹层窗口会各自渲染同一份卡片（双影实证）。
- 实现唯一真相在 `floating.rs` 的「Windows 分离卡二级浮层」注释块与 `capture/windows.rs`（拖拽起点只认胶囊卡）；本节只记结构与意图。

## B.2 浮动条交互规格

### B.2.1 状态机（两窗模型）

早期「结果面板在胶囊内展开」的单窗三态已废弃：结果面板独立为 `ocr` 结果窗
（`IS_OCR = WIN_LABEL === "ocr"`，复用 floating.html），胶囊窗只承载胶囊与二级浮层。

```
Hidden ──selection://captured──▶ Bar（胶囊窗，动作按钮）
Bar ──点击动作──▶ Result（结果窗接管：ocr 流式 / extract 提取面板；胶囊随即隐藏）
Result ──流结束──▶ Done（复制 / 后续动作 / 关闭）
任意状态 ──selection://dismiss / Esc──▶ Hidden
Bar/Result ──新 selection://captured──▶ 定位刷新，回到 Bar（旧结果丢弃）
```

- Phase 联合（floating/App.tsx）：`bar`（胶囊与浮层，胶囊窗）| `extract`（实体提取
  面板，结果窗）| `ocr`（识图 / 划词结果流式，结果窗）；另有钉图：窗口 label 前缀
  `pin-` 进入 pinned 渲染模式，结果窗自身有「钉住」开关（划词导流默认钉住）
- 结果窗尺寸与位置只由用户改变：拖拽缩放（钳制 320–560 × 200–800，跨会话记忆）
  与外观预设，见 §B.1

### B.2.2 防打扰三原则（与 §A.3.4 对应）

1. 出现条件苛刻：必须是"有效新选区"（拖选>6px 或双击，自适应防抖，黑名单/自身/重复全被过滤）
2. 消失干脆：单击空白、Esc、打开新选区即隐藏
3. 全程无声音、无闪烁、不抢焦点

### B.2.3 视觉基调

- **实心原生面板**（macOS popover 质感）：不透明表面色 + 0.5px 发丝描边 + 大阴影，跟随系统深/浅色（不用毛玻璃半透明）
- **悬浮操作层 = 反色面**（2026-10-20 定稿）：凡悬浮在正文之上的操作元素（溢出胶囊堆、子菜单 chip、行侧子菜单）用**主题反极性的不透明实底**——亮色主题 `#1c1c24` 墨底白字，暗色主题近白底墨字（墨底叠暗面板对比不足，实测发糊后改为彻底反色）；hover 实心品牌色 + 白字，默认服务用品牌色文字标记。不用毛玻璃（评审否决）、不用半透明底与投影（叠正文会透字/糊斑）；承载面板仍走实心 popover 质感
- 动作按钮：**图标 + 短文字**，hover 时图标转强调色；结果面板头部显示动作名 + 流式光标（▍闪烁）+ 复制/收起图标钮
- **宽度自适应**：TS 渲染后测量内容尺寸 → `show_floating_bar(x, y, w, h)` / `resize_floating(w, h)`，Rust 侧锚点定位（右下优先、翻转防出屏）
- **可拖动**：按住动作条/面板头部空白处原生拖拽（`startDragging`），拖动结束防抖同步 `sync_floating_position` 回写状态与锚点
- 出现动画 130ms fade + scale；`prefers-reduced-motion` 下关闭
- 系统字体栈（`-apple-system`），图标内联 SVG（不引图标库）

### B.2.4 「更多」面板与行侧子菜单（定稿 2026-10-19，与 §B.5 同批评审）

- **收纳面板形态不变**：深色竖排卡——刻意与胶囊工具条的语言拉开，防「第二颗胶囊」
  误读；浮层投影/发丝/圆角采用与 §B.5.4 相同的全局 token（换肤不换形）。
- **行侧子菜单方向示能**：触发符按实际弹出方向显示——默认右弹 `›`；面板贴屏幕
  右缘按既有翻转逻辑翻左弹时显示 `‹`（翻转判定复用布局 effect 的既有镜像计算，
  给触发钮加状态类即可）。⌄/⌃ 旋转仅用于向下展开的服务/引擎菜单（披露惯例），
  行侧子菜单不再使用——它只表开合，与弹出方向无关。
- **行侧子菜单统一窄单列菜单卡**（翻译/搜索/Obsidian 目标——行侧级联或 ⌄ 下开
  同一形态，可变长列表内滚）；横排 chips 仅用于结果窗胶囊堆（§B.5.3）。
  真机评审曾试过「行侧全部 chips 化」与「固定小集合 chips 化」，均因形态割裂 /
  长列表横排过宽回退——最终统一为竖排菜单卡。
- **不变项**：hover 驻留 300/350ms、点外收起、新选区回收（均已有，不动）；
  「无容器胶囊堆」不引入胶囊条——胶囊条子菜单是选择器语义，保持菜单卡
  （形态差异的理由见 §B.5.5 淘汰记录的对照结论）。

## B.3 动作注册表（TS 层核心抽象）

```ts
interface ActionDef {
  id: string;                      // 内置：'translate' | 'explain' | ...；自定义：'c:<base36>'
  label: string;                   // 「翻译」
  kind?: "ai" | "local";           // ai = 走模型流式（提示词见 §C.3）；local = 前端本地处理
  prompt?: string;                 // 仅自定义动作携带：它就是该动作的 system 全文
  icon?: string;                   // 仅自定义动作携带：lucide 图标名（shared/icons.tsx）
  when?(text: string): boolean;    // 上下文可见性谓词
}
```

消费端不直接读 `ACTIONS`，而是读合并视图 `actionRegistry(settings.customActions)`——
内置在前、自定义在后，各自再按 `settings.actionOrder` 排；开关语义在合并前筛（内置查
`settings.actions`，自定义看对象自身的 `enabled`）。新增内置动作 = 注册一个对象；
用户新增动作 = 设置页「划词」卡片的「新建 AI 动作」，两者对 Rust 都是零改动。

AI 动作的消息体为 `[{role:"system", content: 生效提示词}, {role:"user", content: 选中文本}]`：
内置动作 system 取 `settings.actionPrompts[id]`（用户覆盖），为空则回落 `DEFAULT_PROMPTS[id]`；
自定义动作直接用它自带的 `prompt`。两条路径都经 `actionPrompt()` 收口，
每条提示词自包含、无共享拼接段——保证设置页"编辑框所见即所发"。

> 演进方向（统一动作模型，见 [01 §6](./01-产品定位与规划.md)）：自定义 AI 动作已落地；
> 下一步是接入动作（URL scheme / AppleScript 模板，无状态一次性送达）与变体挂载
> （`CustomAction.under` 字段已预留：把用户 prompt 挂进内置动作的二级展开列表而非新增胶囊位）。

## B.5 结果窗口动作行：溢出收纳与「更多」浮层（定稿）

> 交互方案已经可交互示例评审定稿（2026-10-19，用户确认）；本文记录结论与几何，
> 迭代过程的淘汰原因见 §B.5.5——新增误报类需求时先读它，别把淘汰形态改回来。

### B.5.1 溢出收纳（单行模型）

结果窗口底部动作行**单行不折行**（`flex-wrap: nowrap` + `overflow: hidden`）：末位元素
右缘越过行右缘 → 尾部动作收进行尾「更多 ⌃N」收纳钮。放回用迟滞防抖（行右缘富余
≥ 一个按钮位 56px 才放回一个），窗口/内容尺寸变化由 ResizeObserver 触发重测；量溢出
不能用 `scrollWidth`（放得下时恒等于 clientWidth），必须用末位元素几何右缘。
收纳与展开均**不改窗口尺寸**——窗口尺寸只由用户拖动 / 外观预设决定（§B.1）。

### B.5.2 「更多」展开形态：竖排胶囊堆

- **形态**：竖排胶囊堆从行尾向上浮起。**无容器卡**——每颗胶囊是独立浮层，配色
  为墨面反色（2026-10-20 翻案「实底+发丝+投影」：白胶囊贴白面板区分不开，见
  §B.2.3 悬浮操作层），与动作行按钮同语言（图标 + 短文字）；hover = 实心品牌色
  + 白字，展开态 = 浅靛文字标记，不用半透明底（会透出底下正文）
- **位置**：堆内胶囊**右对齐**——带子操作的胶囊尾部 `<` 触发器连成一条竖列；
  内容右缘贴窗口内容区（13px，对齐 `.ocr-main` 水平 padding）；底边常态 =
  动作行上方 8px，「回到底部」钮可见（流式 + 上翻）时抬到 34px 让出其 6+22px
  带（rail-lift，150ms 过渡）
- **容量**：限高 264px ∧ 面板剩余高度，超出堆内滚动（滚动容器隐形；无容器卡时
  投影用「内边距 + 负 margin」补偿，防止被滚动边界裁切）
- **行为**：点胶囊执行并收起；带 `<` 的胶囊主区域同样是执行（默认服务/目标）；
  hover 驻留规则与胶囊条一致（300ms 展开 / 350ms 收起）

### B.5.3 子菜单：横向 chips 行侧级联

- **触发器**：带子操作的胶囊尾部用 `<`（chevron-left）——**方向即行为**（chips 向左
  展开），不用 ⌄ 加旋转（⌄ 承诺向下，示能不符）
- **形态**：横向 chips 条（胶囊形 chip），**独立浮层、无容器卡**；选中项品牌色淡染
  实底 + 品牌色描边
- **定位**：chips 右缘距触发胶囊左缘 6px，**垂直居中对齐该胶囊**；可用宽 = 胶囊
  左缘 − 面板左缘 − 14px（左呼吸 8 + 缝 6），超限换行、行右对齐；不压动作行、
  不顶出面板
- **核心约束**：子菜单是独立浮层——**堆的宽度与高度永不随子菜单变化**（子菜单
  拼进卡片的形态全部因此淘汰，见 §B.5.5）
- **行为**：点 chip 执行并收起全部；同一时刻至多一个子菜单（`pmenu:*` 状态机
  复用）；**光标离开「胶囊堆 ∪ chips」区域 150ms 后收回 chips（主堆保留）**——
  短防抖吸收边缘抖动/路过，仍无需碰到别的子菜单触发钮；点结果区/空白处收起
  全部（结果窗的「点外收起」分支）。行 ⌄ 槽位子菜单（翻译/搜索/目标）同规则：
  区域 = 触发槽位 ∪ 槽位 chips，离开即收；**展现改为动作行上方浮层 chips**——
  左缘对齐触发槽位、底边距行上缘 8px、限宽换行 + 限高内滚；chips 用 8px 方圆角
  （与动作行按钮同档，区别于行侧子菜单的胶囊形），配色为墨面反色（§B.2.3
  悬浮操作层：默认服务浅靛文字标记、hover 实心品牌色 + 白字，曾用的「半透明
  fill/小投影」叠正文透字或糊斑，均废弃）；窗口生长机制
  （RESULT_MENU_GROW + 冻结/解冻）退役，尺寸模型回到「只由拖动/预设改变」
- **动效（2026-10-20 定稿，三类二级表面统一）**：槽位 chips / 胶囊堆 / 行侧
  chips 共用同一 token（时长 150ms 入 / 110ms 出 + expo-out 曲线），菜单作为
  **一个物体整体浮现**——从锚点方向 3px 位移 + 轻缩放入场（transform-origin
  锚定触发侧），纯收起/切换走短退场（App.tsx 以 fading 快照续挂旧内容淡出，
  与新菜单入场交叉）；执行动作的收起仍瞬时（结果区接管，退场不抢戏）。
  逐颗 26ms 级联已废弃：读作「排队蹦出」且拖到 300ms+，单颗 transform 还会
  污染触发胶囊的锚点测量（旧版行侧 chips 被迫只淡入的根因）；胶囊堆入场
  位移期间量锚点会有 ≤3px 偏移，由 `animationend` 复核摆位兜底

### B.5.4 几何常量

| 常量 | 值 | 出处 |
|---|---|---|
| 堆内容右缘贴窗口内容区 | 13px | `.ocr-main` 水平 padding |
| 堆内容底边 | 动作行上方 8px；「回到底部」钮可见时 34px（rail-lift，150ms 过渡） | 常态贴近动作行；流式上翻时让出 6+22px 带 |
| chips 条距触发胶囊 | 6px | 级联缝 |
| chips 垂直对齐 | 与胶囊中心对齐 | 因果就近 |
| 堆限高 | min(264px, 面板剩余高度) | `.pop.overflow` 既有能力 + 不顶出上缘 |
| chips 限宽 | 胶囊左缘 − 面板左缘 − 14px | 左呼吸 8px + 缝 6px |
| 浮层投影 | 静止无投影（0.5px 发丝定界）；hover 极轻 `0 2px 8px rgba(0,0,0,.1)` | 相邻 chips 的小阴影会连成灰带（浅色尤甚），故静止零投影、hover 才浮起 |

### B.5.5 淘汰记录（为什么）

| 形态 | 淘汰原因 |
|---|---|
| 竖排菜单行 + 尾部 chips（首版实现） | chips 拼进卡片 → 卡片宽度随子菜单变化 |
| 竖排胶囊堆 + 胶囊内 chips 第二行 | 同上——卡片尺寸突变 |
| 横排胶囊条 + 上方窄菜单 | 动作多时横排容量不足（换行/横滚体验差） |
| 子菜单正上方弹出（竖排堆内） | 会盖住堆内上方胶囊；向左弹进空白结果区任何位置都成立 |

结论：**主堆竖排**（容量天然大）**+ 子菜单独立浮层**（对堆尺寸零影响）是同时满足
「宽度恒定、容量、就近锚定」的唯一组合。

### B.5.6 实现衔接

- 向上浮起定位复用 `.pop.overflow.rail`（右 13px / 底 71px = 3 + 0.5 + 5 + 26 + 34）
- `pmenu:*` 状态机与 hover 驻留整套复用，仅换渲染与横向定位
- 「点外收起」走 `onStageMouseDown` 的 IS_OCR 分支（点 `.pop` 与 `.ocr-actions`
  之外收起；动作行内点击不收，保证「更多」钮开合不被 mousedown 抢先）
- 胶囊条自己的收纳面板**不受本节影响**：竖排深色菜单是胶囊语境的刻意差异化
  （避免"第二颗胶囊"误读），Windows 分离卡下它还是独立弹层窗口

# C. AI 服务层

> 核心决策：**AI 编排在 TS，传输在 Rust；热路径零 AI 框架**

## C.1 分工

| 职责 | 归属 | 说明 |
|---|---|---|
| 动作定义 / prompt 模板 | TS `shared/actions.ts` | 产品迭代最快处，纯 TS |
| 流式客户端 / 渲染 | TS `shared/ai.ts` + 组件 | Channel 订阅 |
| 传输（OpenAI 协议 SSE） | Rust `ai.rs`（哑管道） | 无任何 AI 逻辑，解决 CORS，兼容任意 OpenAI 兼容端点 |
| Provider 配置 | Rust `settings.rs` | base_url/key/model |
| 未来：tool loop / agent | TS（M2 引入 Vercel AI SDK） | 见 §C.6 |

> 为什么传输放 Rust：WebView 内直连任意 BYOK 端点会撞 CORS（第三方 OpenAI 兼容端点大多不带 CORS 头）。Rust 管道 ~100 行、协议稳定（chat/completions 多年未变），是兼顾"任意端点可用"与"热路径零依赖"的最稳解。M2 若引入 AI SDK，可给它注入同一管道作为自定义 transport。

## C.2 调用契约（见 [02-架构](./02-架构设计.md) §3.2）

`invoke('ai_chat', { messages, providerId?, channel })` → Channel 推送 `{type:"delta"|"done"|"error", ...}`。

Rust 侧实现要点：
- `POST {base_url}/chat/completions`，`stream: true`，`Authorization: Bearer {api_key}`
- reqwest `bytes_stream` → SSE 缓冲解析（按空行分帧，取 `data:` 行，`[DONE]` 终止）→ 每帧 `choices[0].delta.content` 发 delta
- 60s 超时；任何网络/HTTP 错误 → `{type:"error"}`（前端展示重试按钮，不崩溃）
- Key 仅在 Rust 内存中取自 settings，不回传给前端持久层

## C.3 Prompt 模板（内置动作全量）

**全文以 `src/shared/actions.ts` 的 `DEFAULT_PROMPTS` 为准**（设置页的「系统默认」直接读该常量，避免文档/代码双份维护）。三条模板共同遵守的设计约束：

- **自包含**：每条独立成段，不共享拼接前缀——用户在设置页编辑框看到的，就是发给模型的完整 system
- **消息结构**：`system = 生效提示词`，`user = 选中文本`；用户消息永远是原文，不掺模板变量
- **尺度自适应**：不用固定篇幅套所有选区（解释按词/句/段分层，总结按内容体量给 1-2 / 3-5 / 5-8 条）
- **语言显式**：每条自带输出语言规则（总结跟随原文、解释固定简体中文、翻译按方向）
- **反幻觉兜底**：内容不足以支撑动作时，明说并请求更完整文本，不猜、不注水

各自要点：

| 动作 | 要点 |
|---|---|
| translate | 中文→英文、其他→简体中文；先判领域语体并保持同等语域；术语从通行译法；人名/代码/URL 原样；输出 `【译文】`+可选 `【要点】`（浮动条 `splitTranslate` 容错解析，用户删掉结构不会破坏渲染） |
| explain | 是什么 / 为什么重要 / 关键点；术语首现给定义；例子或类比至多一句；超出选区范围的信息标注不确定 |
| summarize | 只输出要点、无前言无总结语；每条 ≤30 字写结论本身；关键数字与限定条件不得为简洁丢掉 |

> 模型路由（未实现）：翻译/总结走便宜快模型，解释/问答走旗舰模型。Provider 结构已预留 `model` 字段，可按动作扩展为 `models: {default, fast}`。
> 自定义动作（[01 §6](./01-产品定位与规划.md)）落地后，用户新建的 AI 动作复用同一 `actionPrompts` 覆盖机制，本节模板即"内置动作的默认值"。

## C.4 错误与状态

| 场景 | 表现 |
|---|---|
| 未配置 Provider / Key 为空 | 点击动作 → 面板提示"请先在设置中配置模型"，按钮直达设置 |
| 网络/超时/401 | error 事件 → 面板显示错误摘要 + 重试按钮 |
| 流中断 | 同上（已收到部分文本保留展示） |
| 结果为空 | 显示"（无结果）" |

## C.5 安全

- prompt 注入：选中文本为用户主动选择，不做注入防护（结果仅展示，无工具权限，无攻击面）；agent 具备工具后须引入注入防护（工具白名单 + 确认机制）
- 隐私：仅发送选中文本；无遥测

## C.6 演进：从"哑管道"到 Agent

1. **浅 agent（AI 搜索/问一问）**：TS 层引入 Vercel AI SDK——`streamText` + tool（`web_search`）。搜索工具实现：搜索 API（Tavily/博查）注册为 tool；传输层复用 Rust 管道（AI SDK 自定义 transport）或评估 `@tauri-apps/plugin-http` 流式直连
2. **上下文增强**：捕获事件载荷加 `context`（AX 周边段落），解释/问一问模板消费它——这是对标竞品的体验代差
3. **统一动作模型（M3 主线）**：注册表升级为"内置 + 用户数据"合并——自定义 AI 动作（用户 prompt 模板）、接入动作（URL scheme / AppleScript 模板，**无状态一次性送达**，不建收藏存储）、workflow 多步骤链；架构落点见 [02 §6](./02-架构设计.md)
4. **深度模式（M4）**：Node sidecar（deepagents/LangGraph.js）按需拉起，以"重动作"身份挂入注册表，不占常驻内存

**自建 vs 框架的边界**：浅任务（≤5 次工具调用）用 AI SDK/自建 loop；长任务（规划/子代理/长产出）用 deepagents sidecar。绝不在热路径引入任何框架。
