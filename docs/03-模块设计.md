# A. 划词捕获（capture）

> 全项目风险最高模块，MVP 仅实现 macOS；Windows 为 M2，接口已预留

## A.1 职责与非职责

- **职责**：全局监听鼠标 → 判定"选词动作" → 经 AX 读取选中文本 → 过滤（黑名单/自身/重复）→ 发 `selection://captured` / `selection://dismiss` 事件
- **非职责**：窗口显示（窗口管理）、文本处理（TS 层）

## A.2 组件结构

```
src-tauri/src/capture/
├── mod.rs          # CaptureEvent 定义、平台分发、启动入口
├── macos.rs        # macOS：CGEventTap + AX 查询（MVP 实现）
└── windows.rs      # Windows：UI Automation（M2 占位，见 §A.7）
```

平台通过 `#[cfg(target_os = ...)]` 分发，两个后端实现同一签名：

```rust
pub fn start(tx: Sender<CaptureEvent>) -> Result<()>;   // 内部自建线程
```

## A.3 macOS 实现

### A.3.1 双线程模型

```
[CGEventTap 线程]  CGEventTapCreate(kCGSessionEventTap, listen-only, mask=MouseDown|Up|Dragged)
        │  回调仅做一件事：把 (事件类型, 坐标, 时间戳) 扔进 mpsc channel
        ▼
[Worker 线程]  状态机（防抖/判定）→ sleep(200ms) → AX 查询 → 过滤 → app_handle.emit(...)
```

> listen-only tap 不消费/修改事件，对用户无感，被系统自动禁用的风险极低；回调内不做任何重活（AX 查询绝不放进回调）。
>
> **tap 层级实测（2026-09，macOS 26 Intel）**：`kCGSessionEventTap` 收不到拖选事件（仅偶发单击），`kCGHIDEventTap` 全部正常 → 默认采用 HID 级，`SHICI_TAP=session` 环境变量可切回对照。此偏差需在 Windows/新版 macOS 上复核。

### A.3.2 选词判定状态机

| 输入 | 规则 |
|---|---|
| LeftMouseDown | 记录 `down_pos / down_time` |
| LeftMouseDragged | 更新 `last_pos` |
| LeftMouseUp | `drag_dist = |up - down|`；`is_double_click = (本次up时间 - 上次up时间 < 400ms) 且位移 < 10px` |
| 判定为选词 | `drag_dist > 6px` **或** `is_double_click` → 进入防抖查询；否则视为普通点击 |

- 防抖：判定为选词后 `sleep(debounce_ms=200)` 再查 AX（等待应用完成选区更新）
- 普通单击：若浮动条当前可见 → 发 `selection://dismiss`（点击空白隐藏浮动条）

### A.3.3 文本查询链（AX 优先）

```
AXUIElementCreateSystemWide()
 → CopyAttributeValue(kAXFocusedApplicationAttribute) → 聚焦应用 app
    ├─ AXUIElementGetPid(app) → pid ①自身过滤 ②proc_pidpath 取应用路径→黑名单匹配
    └─ 文本查询链（按实现顺序，任一成功即返回）：
        ① 聚焦元素 AXSelectedText（主路径）
        ② 聚焦元素 AXSelectedTextRange → AXStringForRange（参数化范围回退，
          覆盖部分 Qt 自绘文本视图——不暴露 SelectedText 但支持范围取值）
        ③ 应用级 AXSelectedText（部分应用只在此暴露）
        ④ Chromium/Electron 系轻推（AXEnhancedUserInterface / AXManualAccessibility
          置 true 后重试 ①②③）
        ⑤ 坐标定位：AXUIElementCopyElementAtPosition（top-left 原点，与 CGEvent 同系）
          取鼠标处元素 → 沿 AXParent 上溯（≤5 层）尝试①②，绕开聚焦链路
        ⑥ 兼容模式（常开兜底）：快照剪贴板 → CGEventPost 模拟 ⌘C →
          轮询剪贴板变化（10ms × 60，上限 600ms）→ 取词 → 还原快照
        ⑦ 有界子树扫描：聚焦元素子树 → 聚焦窗口子树（各 64 节点 / 深度 6，DFS 尝试①②）。
          覆盖聚焦元素停留在输入框、真实选区在兄弟/子孙节点的场景；
          仅 ⑥ 未命中时触发，可能超出 A.5 的 30ms 查询预算（失败兜底，可接受）
    └─ Safari 专属分支（AX 链路失败且聚焦应用为 Safari 时，先于 ⑥ 执行）：
        osascript `do JavaScript "window.getSelection().toString()"` 读取选区
        （需 Safari 开发菜单开启「允许来自 Apple 事件的 JavaScript」；未开启/超时 → 落到 ⑥）
```

### A.3.3.1 兼容模式（模拟 ⌘C，常开兜底）

AX 链路全部失败时触发（行业通行解，参考 Easydict GUIDE / issue #84）：

```
快照剪贴板文本 → CGEventPost 模拟 ⌘C → 轮询剪贴板变化（10ms × 60，上限 600ms）
→ 取词 → 还原快照（原无文本则清空）→ 走正常 Selection 链路（黑名单/去重仍生效）
```

取词失败仍静默；剪贴板为非文本内容时无法还原（已知限制）。

- CF 内存管理：`Copy*` 返回 +1 引用，用 `CFString::wrap_under_create_rule` 接管，drop 自动 `CFRelease`
- **查询失败的语义 = 静默失败**：不发事件、不提示
- MVP 定位直接用**鼠标坐标**（事件自带），不做 AX `BoundsForRange`（列入 M2 增强，可让浮条贴住真实选区，见 ADR-06）

### A.3.4 过滤规则（顺序即优先级）

1. `pid == 自身` → 跳过（主窗口/浮动条内选词不触发）
2. 应用 bundle 路径命中 `app_blacklist` → 跳过
3. 文本为空 / 与上次已捕获文本相同且坐标相近（< 4px）→ 跳过（重复触发抑制）

### A.3.5 权限

- 启动时 `AXIsProcessTrustedWithOptions(prompt=false)` → 发 `capture://permission`
- 自检页按钮：`AXIsProcessTrustedWithOptions(prompt=true)` + 打开 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`
- **输入监控（Input Monitoring）**：缺失时 listen-only tap 收不到其他应用的事件（浮动条不弹）；自检页经 `capture_status.listenEventAccess` 展示，`request_listen_access` 以 `CGRequestListenEventAccess` 发起授权，未通过时代开 `Privacy_ListenEvent` 面板
- **AX 服务实测**：`capture_status.axServiceOk` 以 system-wide 聚焦应用查询区分「TCC 信任」与「AX 服务实际放行」（缓存异常/代持授权时割裂）
- tap 创建失败（未授权时 CGEventTapCreate 返回 NULL）→ 重试定时器（每 3s），授权后自愈
- **开发模式授权**：`tauri dev` 的裸二进制不会出现在辅助功能列表，需给终端 App 授权或手动添加二进制——指引放 README（步骤①），不进产品 UI
- **打包版授权注意**：ad-hoc 签名下 TCC 以 CDHash 记录授权，**每次重新构建均需在「辅助功能 / 输入监控」中删除并重新添加**，否则列表看似已勾选、实际指纹失效

## A.4 事件载荷

```rust
pub struct CaptureEvent {
    pub text: String,     // 选中文本（原始，未 trim）
    pub x: f64,           // 鼠标全局坐标（macOS = logical point，与 Tauri LogicalPosition 同系）
    pub y: f64,
    pub app: String,      // 进程路径（黑名单/展示用）
}
```

## A.5 性能预算

| 环节 | 预算 |
|---|---|
| 回调入队 | < 10μs |
| 防抖等待 | 200ms（固定） |
| AX 查询 | < 30ms（实测通常 < 5ms） |
| **松手→事件发出** | **≤ 240ms** |

常驻开销：tap 线程阻塞在 RunLoop（0% CPU）；Worker 线程阻塞在 recv（0% CPU）。

## A.6 已知覆盖缺口（预期管理）

| 场景 | AX 可用性 | MVP 行为 |
|---|---|---|
| Safari | ⚠️ 不暴露 AX SelectedText | AppleScript 取词（需 开发菜单 → 允许来自 Apple 事件的 JavaScript）；未开启自动走 ⌘C 兜底 |
| Chrome / 备忘录 / VS Code | ✅ / ⚠️ 需轻推 | 正常 |
| Pages / Keynote / Word（自绘文本） | ❌ | 兼容模式（⌘C）取词 |
| 微信 4.x（Qt 自绘主界面） | ❌ 不暴露 SelectedText | 自动走兼容模式兜底（模拟 ⌘C），正常弹出 |
| 微信 3.x / QQ NT（Electron） | ✅ / ⚠️ 需轻推 | 正常 / 轻推后正常 |
| 部分 Electron 旧应用 | ⚠️ 取决于版本 | 兼容模式（⌘C）取词 |
| 自绘 UI 应用（部分 PDF 阅读器） | ❌ | 兼容模式（⌘C）取词 |
| 远程桌面 / 虚拟机内部 | ❌ | 兼容模式（⌘C）取词 |
| DRM 内容（如部分视频字幕） | ❌ | ⌘C 亦不可复制，静默失败 |

自检页（§B.4）承担"哪个应用能用"的预期管理职责。

## A.7 Windows 预设计（M2）

- 监听：`SetWindowsHookEx(WH_MOUSE_LL)` 低级钩子（与 CGEventTap 对位）
- 查询：UI Automation —— `FocusChanged`/`TextSelectionChanged` 或在 mouseup 后 `ElementFromPoint` → `TextPattern::GetSelection` → `DocumentRange.GetText`
- 坐标：物理像素，需按 `DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2` 换算（与 macOS 不同系，窗口管理层统一封装）
- 已知坑：Chromium 系应用需激活 UIA 支持；提权应用（任务管理器）不可读；文本框类型差异大——按 [04-技术选型](./04-技术选型.md) 排期专项 spike

# B. 窗口与交互（UI）

> 覆盖浮动条窗口、主窗口、交互规格与视觉基调

## B.1 窗口规格

| 属性 | 浮动条 `floating` | 主窗口 `main` |
|---|---|---|
| 初始尺寸 | 328×54（收起） | 760×560 |
| 展开尺寸 | 380×420（结果面板，`resize_floating` 动态调整） | — |
| 装饰 | 无边框、透明、无阴影 | 系统标准 |
| 层级 | 置顶 + 不进任务栏 | 常规 |
| 焦点 | **不抢焦点**（不 show/focus，纯鼠标交互） | 正常 |
| 定位 | `show_floating_bar(x,y)`：光标右下偏移 (12, 16)，防出屏钳制 | 记忆位置 |
| 生命周期 | 常驻隐藏，show/hide | 常驻 |

### 防出屏钳制算法

```
bar_w, bar_h = 当前窗口逻辑尺寸
monitor = x,y 所在显示器（取 scale_factor 后统一为逻辑坐标）
new_x = clamp(x + 12, 0, monitor.max_x - bar_w)
new_y = (y + 16 + bar_h > monitor.max_y) ? y - bar_h - 8 : y + 16   // 底部放不下→放到光标上方
```

## B.2 浮动条交互规格

### B.2.1 状态机

```
Hidden ──selection://captured──▶ Bar（胶囊，动作按钮）
Bar ──点击动作──▶ Expanding（结果面板流式）
Expanding ──流结束──▶ Done（可 复制/关闭）
任意状态 ──selection://dismiss / Esc──▶ Hidden
Bar/Expanding ──新 selection://captured──▶ 定位刷新，回到 Bar（旧结果丢弃）
```

### B.2.2 防打扰三原则（与 §A.3.4 对应）

1. 出现条件苛刻：必须是"有效新选区"（拖选>6px 或双击，200ms 防抖，黑名单/自身/重复全被过滤）
2. 消失干脆：单击空白、Esc、打开新选区即隐藏
3. 全程无声音、无闪烁、不抢焦点

### B.2.3 视觉基调

- **实心原生面板**（macOS popover 质感）：不透明表面色 + 0.5px 发丝描边 + 大阴影，跟随系统深/浅色（不用毛玻璃半透明）
- 动作按钮：**图标 + 短文字**，hover 时图标转强调色；结果面板头部显示动作名 + 流式光标（▍闪烁）+ 复制/收起图标钮
- **宽度自适应**：TS 渲染后测量内容尺寸 → `show_floating_bar(x, y, w, h)` / `resize_floating(w, h)`，Rust 侧锚点定位（右下优先、翻转防出屏）
- **可拖动**：按住动作条/面板头部空白处原生拖拽（`startDragging`），拖动结束防抖同步 `sync_floating_position` 回写状态与锚点
- 出现动画 130ms fade + scale；`prefers-reduced-motion` 下关闭
- 系统字体栈（`-apple-system`），图标内联 SVG（不引图标库）

## B.3 动作注册表（TS 层核心抽象）

```ts
interface Action {
  id: 'translate' | 'explain' | 'summarize' | ...   // 可扩展/自定义
  label: string;            // 「翻译」
  icon: string;             // svg id
  buildMessages(text: string): ChatMessage[];   // prompt 模板见 §C.3
}
```

浮动条按 `settings.actions` 过滤渲染；新增动作 = 注册一个对象 + Rust/设置零改动。

> 演进方向（统一动作模型，见 [01 §6](./01-产品定位与规划.md)）：注册表从"代码内置"升级为"内置 + 用户数据"合并渲染，新增类型 = 自定义 AI 动作（用户 prompt 模板）与接入动作（URL scheme / AppleScript 模板，无状态一次性送达）。

|---|---|---|

# C. AI 服务层

> 核心决策：**AI 编排在 TS，传输在 Rust；热路径零 AI 框架**

## C.1 分工

| 职责 | 归属 | 说明 |
|---|---|---|
| 动作定义 / prompt 模板 | TS `shared/actions.ts` | 产品迭代最快处，纯 TS |
| 流式客户端 / 渲染 | TS `shared/ai.ts` + 组件 | Channel 订阅 |
| 传输（OpenAI 协议 SSE） | Rust `ai.rs`（哑管道） | 无任何 AI 逻辑，解决 CORS，兼容任意 OpenAI 兼容端点 |
| Provider 配置 | Rust `settings.rs` | base_url/key/model |
| 未来：tool loop / agent | TS（M2 引入 Vercel AI SDK） | 见 §C.6 |

> 为什么传输放 Rust：WebView 内直连任意 BYOK 端点会撞 CORS（第三方 OpenAI 兼容端点大多不带 CORS 头）。Rust 管道 ~100 行、协议稳定（chat/completions 多年未变），是兼顾"任意端点可用"与"热路径零依赖"的最稳解。M2 若引入 AI SDK，可给它注入同一管道作为自定义 transport。

## C.2 调用契约（见 [02-架构](./02-架构设计.md) §3.2）

`invoke('ai_chat', { messages, providerId?, channel })` → Channel 推送 `{type:"delta"|"done"|"error", ...}`。

Rust 侧实现要点：
- `POST {base_url}/chat/completions`，`stream: true`，`Authorization: Bearer {api_key}`
- reqwest `bytes_stream` → SSE 缓冲解析（按空行分帧，取 `data:` 行，`[DONE]` 终止）→ 每帧 `choices[0].delta.content` 发 delta
- 60s 超时；任何网络/HTTP 错误 → `{type:"error"}`（前端展示重试按钮，不崩溃）
- Key 仅在 Rust 内存中取自 settings，不回传给前端持久层

## C.3 Prompt 模板（内置动作全量）

所有模板：中文用户输出中文，英文用户输出英文（按选中文本语言自适应）；system 固定人设"简洁、准确、直接给结果、不用客套"。

**translate**（翻译）
```
system: 你是专业翻译。检测输入语言：中文→译成地道英文；其他语言→译成简体中文。
        只输出译文，不解释。保留专有名词、代码、格式。
user:   {text}
```

**explain**（解释）
```
system: 你是耐心的知识助手。解释用户选中的内容：它是什么/为什么重要/关键点。
        用 2-4 段短文，术语首次出现给简明定义。
user:   {text}
```

**summarize**（总结）
```
system: 你是摘要助手。将选中内容提炼为要点：≤5 条 bullet，每条 ≤20 字，按重要性排序。
        只输出要点，不加前言总结语。
user:   {text}
```

> 模型路由：翻译/总结走便宜快模型，解释/问答走旗舰模型。Provider 结构已预留 `model` 字段可按动作扩展为 `models: {default, fast}`。自定义动作开放 prompt 编辑后（[01 §6](./01-产品定位与规划.md)），本节模板即"默认值"。

## C.4 错误与状态

| 场景 | 表现 |
|---|---|
| 未配置 Provider / Key 为空 | 点击动作 → 面板提示"请先在设置中配置模型"，按钮直达设置 |
| 网络/超时/401 | error 事件 → 面板显示错误摘要 + 重试按钮 |
| 流中断 | 同上（已收到部分文本保留展示） |
| 结果为空 | 显示"（无结果）" |

## C.5 安全

- prompt 注入：选中文本为用户主动选择，不做注入防护（结果仅展示，无工具权限，无攻击面）；agent 具备工具后须引入注入防护（工具白名单 + 确认机制）
- 隐私：仅发送选中文本；无遥测

## C.6 演进：从"哑管道"到 Agent

1. **浅 agent（AI 搜索/问一问）**：TS 层引入 Vercel AI SDK——`streamText` + tool（`web_search`）。搜索工具实现：搜索 API（Tavily/博查）注册为 tool；传输层复用 Rust 管道（AI SDK 自定义 transport）或评估 `@tauri-apps/plugin-http` 流式直连
2. **上下文增强**：捕获事件载荷加 `context`（AX 周边段落），解释/问一问模板消费它——这是对标竞品的体验代差
3. **统一动作模型（M3 主线）**：注册表升级为"内置 + 用户数据"合并——自定义 AI 动作（用户 prompt 模板）、接入动作（URL scheme / AppleScript 模板，**无状态一次性送达**，不建收藏存储）、workflow 多步骤链；架构落点见 [02 §6](./02-架构设计.md)
4. **深度模式（M4）**：Node sidecar（deepagents/LangGraph.js）按需拉起，以"重动作"身份挂入注册表，不占常驻内存

**自建 vs 框架的边界**：浅任务（≤5 次工具调用）用 AI SDK/自建 loop；长任务（规划/子代理/长产出）用 deepagents sidecar。绝不在热路径引入任何框架。
