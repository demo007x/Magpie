# 技术选型 · 决策记录（ADR）

> v0.1 · 2026-09 · 记录"为什么是它"，供未来回顾与翻案

## ADR-01 跨平台框架：Tauri 2 ✅

- **结论**：Tauri 2（Rust 核心 + 系统 WebView），UI 层 React + Vite + TypeScript
- **理由**：7×24 后台常驻工具，内存是硬指标（Electron 常驻 200~400MB 不可接受）；系统级能力（鼠标钩子/AX/无框窗口）本就需要原生代码，Rust 直达；Tauri 2 稳定且支持双窗口/透明/置顶/Channel 流
- **否决**：Electron（体积/内存）、Flutter Desktop（系统级能力弱）、双原生（人力×2）

## ADR-02 语言分层：Rust 系统层 + TS AI 编排层 ✅

- **结论**：划词捕获、窗口管理、存储、SSE 传输在 Rust；动作注册表、prompt、流式渲染、未来 agent 在 TS（WebView 内）
- **理由**：Rust AI 生态薄（2026-09 调研：Rig ~6.7k stars / genai 0.5.x / Swiftide 活跃 / **langchain-rust 维护时断时续不采用**），而 AI 功能迭代最快，应放在生态最厚的 TS 侧；Rust 只守契约面窄且五年不变的部分
- **否决**：全 Rust 自建 agent（逆生态风口）、Python sidecar（分发噩梦）、AI 逻辑全进 Rust

## ADR-03 MVP 传输：Rust SSE 哑管道 ✅（非浏览器直连）

- **结论**：`ai_chat` 命令 = Rust reqwest 流式转发 OpenAI 兼容 SSE，经 Tauri Channel 推给 TS
- **理由**：BYOK 场景下任意第三方端点大概率无 CORS 头，WebView 直连不可靠；管道 ~100 行、协议（chat/completions）多年稳定、对框架零依赖
- **翻案条件**：M2 引入 Vercel AI SDK 时，优先评估其自定义 transport 复用本管道 / `plugin-http` 直连流式，若成立可精简

## ADR-04 AI 框架策略：热路径零框架，分层引入 ✅

- **结论**：MVP 不引入任何 AI 框架（prompt 模板 + 流式管道即可）；M2 浅 agent（搜索/问答）引 **Vercel AI SDK**；M4 深度研究模式按需拉起 **deepagents**（Node sidecar）；RAG（M3）用 Rust `sqlite-vec` + Swiftide 思路自建管道
- **理由**：见 [05-AI服务层 §6](./05-模块设计-AI服务层.md)；消费级划词工具 90% 场景为浅任务（≤5 次工具调用），框架收益为负（延迟/体积/调试复杂度）
- **背景**：曾评估 LangChain（重、抽象厚）与 deepagents 做核心（长任务错配、双语言栈），均否决为"地基"，保留为"可选挂件"

## ADR-05 文本捕获：无障碍 API-only，无剪贴板 ✅

- **结论**：macOS CGEventTap + AX；Windows M2 用 UIA；**全流程不读/写剪贴板**；查询失败静默
- **理由**：产品叙事（无痕、不污染剪贴板）+ 隐私差异化；剪贴板兜底列为"未来默认关闭的高级选项"
- 详见 [03-捕获](./03-模块设计-划词捕获.md)

## ADR-06 浮动条定位：鼠标坐标而非 AX 选区 Bounds（MVP）✅

- **结论**：MVP 用 mouseUp 坐标定位；AX `BoundsForRange` 贴选区定位列入 M2
- **理由**：省去参数化属性查询的跨应用兼容性风险，MVP 风险集中度管理；体验差异可接受

## ADR-07 密钥存储：MVP 明文 JSON，M2 迁 keyring ⚠️

- **结论**：`settings.json` 明文存 Key（与主流 BYOK 工具现状一致），设置页明示用户；M2 迁系统钥匙串（`keyring` crate），`settings.rs` 预留迁移位
- **风险**：设备被物理访问时 Key 可读——对 MVP 种子用户（极客）可接受
